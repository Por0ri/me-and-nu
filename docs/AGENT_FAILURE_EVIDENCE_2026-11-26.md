# Agent 종료 시 결과·진단 기록 보존

## 확인된 문제와 조사 한계

실제 생성 프로세스가 종료 코드 1로 끝나면서 `result.json`을 남기지 않았다.
Worker는 결과 파일을 종료 기록보다 먼저 읽어서 `artifact_verification_failed`로 표시했고,
프로세스의 표준 출력·오류는 버려져 원래 예외를 확인할 수 없었다.

원본 작업 DB/산출물은 수정하지 않았다. 동일 서버의 네트워크 없는 격리 컨테이너에서
산출물을 읽기 전용으로 연결하고 임시 복제본만 사용했다. 저장된 근거·이미지·작품 연결로
패키지를 복원하여 가짜 provider의 호출 경계까지 진행했다. 실제 모델 호출은 하지 않았다.
당시 provider 응답과 예외가 남지 않았으므로 내부 종료 원인을 특정했다고 주장하지 않는다.

## 변경

- Agent의 콘텐츠 생성 단계에서 예외가 발생하면 요청 식별자, 단계, 예외 종류, 확인된
  사용량을 `generation_failed` 결과로 남긴다. 예외 메시지와 키는 이 결과에 넣지 않는다.
- 실패 결과는 임시 파일을 fsync한 후 같은 디렉터리에서 원자적으로 생성한다.
  기존 결과 파일이 있으면 덮어쓰지 않고 원래 예외를 다시 발생시킨다.
- 사용량 요약은 `complete=false`, `scope=known_usage_only`이다. 전체 비용은 미확정이며,
  확인된 사용량을 전체 사용량이나 무료 실행으로 해석하지 않는다.
- Worker는 표준 출력과 오류를 제한된 크기로 읽으며 허용된 예외 종류·파일명·줄 번호만
  기록한다. 원문 출력, 예외 메시지, 응답 본문·헤더·URL·키를 로그에 저장하지 않는다.
- 비정상 종료, 정상 종료 후 결과 누락, 손상된 산출물을 구분한다. 시간 초과와 작업
  소유권 상실에도 프로세스 그룹을 종료하고 종료 기록을 남긴다.
- 실패 결과는 검수 통과 산출물로 봉인하거나 적재기에 내보내지 않는다.

## 기존 기록과 재개 정책

생성 시작 후 실패한 작업은 `needs_attention`으로 유지한다. 작업/생성 시도 ID,
시작 표시, 기사 중복 방지, 소비한 시도 횟수, 기존 성공·보류 결과와 비용 기록을 보존한다.
프로세스 종료 코드 2도 유료 호출 이후 발생할 수 있으므로 사전 실행 실패로 취급하지 않는다.

이번 변경은 이미 사라진 사용량과 예외를 복원하지 않는다. 결과가 없는 기존 작업을
다시 생성하거나, 성공/생략/비용 0으로 바꾸거나, 다른 작업의 과거 예약금으로 대체하지 않는다.
현재 스케줄러는 미정리 작업이 있는 날을 재개하거나 다음 날로 넘기지 않는다.

재개 전에는 수정 이미지 검증·반영과 별도로 실패한 원래 시도의 사용량 근거 또는
미확정 상태를 보존하는 명시적인 운영자 정리 절차가 필요하다. 이번 작업에서는 운영 DB,
기존 체크포인트, 워커·타이머 설정을 변경하지 않고 유료 생성을 재개하지 않는다.

## 검증

- Worker 진단/산출물/표지 이력/수동 CLI: 35건 통과.
- 일일 횟수 제한 및 비용·중복 이력 보존: 10건 통과.
- 격리 PostgreSQL 작업·복구·중복·마이그레이션: 56건 통과.
- 격리 백엔드 피드·추천·검수·적재: 264건 통과, 선택적 외부 인계 1건 생략.
- Agent 실패 결과·작품 연결·사용량: 36건 통과. 새 실패 경로 13건과 실제 Typer
  하위 프로세스의 비정상 종료가 포함된다. provider는 가짜 함수로 대체했다.
- 기존 Agent 후보 안전성: 18건 통과. Agent 검증은 총 54건이다.

네트워크 없는 테스트 또는 외부 접속이 차단된 임시 DB를 사용했다. 실제 API 키,
서비스 DB 쓰기, 실제 LLM 호출은 사용하지 않았다. 테스트 전용 컨테이너·네트워크는 정리했다.
