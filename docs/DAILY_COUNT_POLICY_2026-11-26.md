## 매일 반복 실행 연결

호스트 실행 관리자 `deploy/daily-generation/scheduled_run.py`와 systemd 서비스·타이머를
추가했다. 승인된 반복 정책의 해시·이미지 버전·등록 출처·40회/20건·적재 대상을 고정하고,
날짜별 계획과 적재 정책을 저장한 뒤 기존 생성기와 적재기를 순서대로 실행한다.

- 5분마다 실행 여부를 확인하되, 완료한 날짜는 생성기를 다시 시작하지 않는다.
- 다음 날에는 마지막 완료 체크포인트를 이어 사용한다. 이전 작업·비용 이력을 지우지 않는다.
- 호스트 파일 잠금과 기존 DB 잠금으로 동시 실행을 차단한다.
- 중단 후 재개 전에 작업 DB와 봉인된 결과를 재검증하고, 완료된 생성은 반복하지 않는다.
- 생성 묶음이 끝난 뒤 통과 결과만 검수 대기로 적재한다. 운영자 승인은 자동으로 만들지 않는다.
- 전날 미완료·미적재 상태, 비용 증거 누락, 설정 변경 등은 자동 재시도 대신 확인을 요구한다.

Linux에서 반복 실행 관리자 테스트 **18건 통과**. 이틀 연속 실행·같은 날 반복 호출·
중단 후 재개·40회 제한·20건 목표·권한 분리를 포함하며 실제 UID 10001의 디렉터리 접근도
검증했다. `--preflight`로 생성 없이 날짜별 계획과 이력·빈 큐를 검사하고, 실제 적용 시
같은 계획을 재사용하는 것도 확인했다. 테스트 작성 중 unittest의 `fail` 메서드를 가린 변수명과 파일명에 포함된
`approved` 문자열을 기능 호출로 잘못 판정한 단언을 바로잡았다.

기존 추천·피드·검수·적재 회귀 **373건과 하위 검사 4건**, 새 정책의 실제 Celery 합성
결과를 사용한 격리 적재 연결 **1건**도 통과했다. 최초 적재 3건, 재적재 신규 0건,
승인 전 노출 0건이며 기존 회원·추천·검수 근거는 유지됐다.
