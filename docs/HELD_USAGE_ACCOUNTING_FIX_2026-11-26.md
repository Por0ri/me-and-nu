# 보류·생략 결과 사용량 보존 — 2026-11-26

기준: 최신 `main`의 `bfe64aab259373251bb9aacaf745b5ecd6f592bc`.
이번 범위는 코드 수정과 무과금 검증, 기존 출처 확장 가능성 검토다.
운영 이미지 배포·자동 생성 재개·서비스 DB 쓰기는 수행하지 않는다.

## 발생 원인

원피스 굿즈 기사 처리 결과는 `expiry_unresolved_held`와 종료 코드 0이었다.
판매/행사 기간을 원문으로 확정할 수 없다는 보류 판단 자체는 정상이다.
하지만 `crawl_generate`의 조기 반환이 사용량 필드를 넣지 않아,
Celery Controller가 `missing_cost_evidence`로 실행을 정지했다.

이전의 결과 파일 없는 Agent 실패와 별개다. 새 보류 결과 파일은 존재하며,
기존 작업·비용 이력과 함께 그대로 보존해야 한다.

## 수정된 동작

- 조기 결과를 공통 함수로 구성해 `usage_records`와 `usage_summary`를 함께 남긴다.
- 대상은 작품 확인 단계/본문 수집 후/팩트 추출 후의 기간 미확정 보류·기간 만료 생략,
  시의성 뉴스 종료, 빈 본문, 작품 미확정, 저장 후 만료·중복 생략이다.
- 호출 전 종료는 명시적으로 0회 사용량을 기록한다. 링크 판단·OCR·작품 확인·팩트 추출이
  먼저 실행됐다면 그 사용량을 한 번씩 보존한다.
- 호출을 시도했는데 제공자 사용량이 누락된 경우에는 미확정 증거를 유지한다.
  실제 호출 후 오류나 사용량 누락을 빈 목록/0원으로 바꾸지 않는다.
- 결과에 불완전한 사용량이 있으면 `cost_accounting.complete=false`로 표시하며,
  기존 Controller의 차단을 유지한다. 증거 없이 비용 0원을 허용하도록 Worker를 완화하지 않는다.
- 보류/생략 판단, 작품·출처·기간 검사, 기존 자료 저장과 중복 판정, 검수·공개 기준은 유지한다.

## 기존 운영 이력

작업 8개/시도 8개, 오늘 시도 4회·검수 통과 1건은 수정 대상이 아니다.
기존 실패 작업과 새 보류 작업, 미확정 비용, 봉인된 결과 파일을 덮어쓰지 않는다.
과거 누락 결과를 다시 읽으면 Controller는 계속 거부한다. 향후 재개에는 별도의
이력 보존·회계 복구 검토가 필요하며 이번 수정만으로 재개되지 않는다.
