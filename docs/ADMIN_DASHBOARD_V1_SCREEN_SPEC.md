# me;nu 1차 관리자 대시보드 화면·기능 명세 초안

- 작성일: 2026-10-20 (Asia/Seoul)
- 문서 버전: 0.1
- 상태: 화면 설계를 위한 제안. 팀의 확정 요구사항 또는 구현 완료 목록이 아님.
- 대상: 초기 애니 도메인, 플랫폼 AI 생성 콘텐츠, 소비자 챗봇을 운영하는 PC 웹 관리자.
- 산출 범위: 메뉴, 화면 구성, 조회 정보, 실행 조치, 상태, 권한, 완료 조건. 디자인 시안·API·DB 구현은 포함하지 않음.
- 검토 기준: 2026-10-19에 확인한 PRD V1.0 대조 사본과 당시 로컬 코드. 배포 환경의 실제 동작은 미검증.

## 1. 설계 기준과 1차 범위

관리자가 아래 질문에 답하고 필요한 처리를 끝낼 수 있어야 한다.

1. 오늘 처리해야 할 문제는 무엇인가?
2. 콘텐츠가 수집·생성·검수·발행 중 어디에서 막혔는가?
3. 사용자가 보는 콘텐츠를 어떻게 수정하거나 노출 중단할 것인가?
4. 신고·회원 요청을 누가 처리하고 있으며, 결과 안내까지 끝났는가?
5. 누가 어떤 근거로 변경했고, 되돌릴 수 있는가?

### 1.1 범위 표기

| 표기 | 의미 |
| --- | --- |
| PRD 유지 | 기존 요구를 관리자 화면으로 구체화 |
| 1차 보완 제안 | 기존 기능을 운영하기 위해 추가하거나 일부를 1차로 앞당기는 제안 |
| 조건부 | 해당 사용자 기능·운영 방식이 실제 출시될 때 함께 제공 |
| 결정 필요 | 기준·정책·담당자가 확정되지 않아 구현 전 합의가 필요한 항목 |

이 문서의 화면 ID는 설계용 식별자다. 기존 PRD의 FR 번호를 대체하거나 새 FR 발급을 의미하지 않는다.

### 1.2 1차에 제공하는 수준

- 조회, 필터, 상세 확인, 담당자 지정, 사유 입력, 수동 조치, 처리 결과·작업 이력 확인을 기본으로 한다.
- 자동 검수 통과 콘텐츠와 미통과 콘텐츠를 구분한다. 모든 콘텐츠에 사람 발행 승인을 강제하지 않는다.
- 미통과 생성물은 사람이 수정·재생성·보류·종결을 결정하며, 수정 뒤에도 필수 검사를 다시 통과해야 한다.
- 운영자는 콘텐츠 공개 상태를 바꾸는 조치와 회원 제재를 구분한다. 플랫폼 생성물의 오류를 일반 회원 제재로 연결하지 않는다.
- 최소 권한 제한, 민감정보 접근 기록, 중요한 변경 재확인은 해당 기능의 첫 출시부터 적용한다.
- 데이터가 없는 지표는 수치를 꾸며 표시하지 않는다. 관리자 API·집계가 필요한 항목은 구현 의존성으로 명시한다.

### 1.3 후속으로 미루는 범위

- 추천 가중치 편집, A/B 실험, 정교한 코호트·퍼널 분석, 실시간 히트맵.
- 프롬프트·모델을 운영 화면에서 자유롭게 편집·배포하는 기능. 1차는 적용 버전 조회까지.
- 복잡한 승인 단계, 자동 담당자 배정, SLA 자동화 엔진, 대규모 일괄 수정.
- 크리에이터 심사·스튜디오·정산, 회원 간 DM 관리, 토론장 운영. 각 서비스 범위 확정 후 추가.
- 인스타그램 발행 자동화·채널별 성과 분석. 웹 콘텐츠의 외부 발행 여부를 기록할 필요가 생기면 먼저 연결 정보만 추가.
- 임의 권한 조합을 만드는 역할 편집기, 전체 개인정보 일괄 다운로드.

## 2. 메뉴와 화면 목록

사이드바는 7개 상위 메뉴로 구성한다. 상세 화면은 목록에서 진입하며, 모든 상세 화면을 사이드바에 나열하지 않는다.

| 상위 메뉴 | 하위 화면 | 화면 ID | 핵심 업무 |
| --- | --- | --- | --- |
| 운영 현황 | 오늘의 운영 현황 | ADM-01 | 처리할 일·장애·공급 현황 확인 |
| 콘텐츠 | 콘텐츠 목록 / 콘텐츠 상세·검수 | CNT-01 / CNT-02 | 생성물 검토, 정정, 발행, 숨김·복구 |
| AI·수집 작업 | 작업 목록·상세 / 챗봇 운영 | OPS-01 / OPS-02 | 실패 원인 확인, 재처리, 답변 품질 점검 |
| 회원·요청 처리 | 회원 / 일반 신고 / 제재·이의 / 권리침해 / 개인정보 요청 / 유출 대응 | USR-01 / CASE-01~05 | 계정과 사건별 처리 및 결과 안내 |
| 분류·소스 | 분류 관리 / 수집 소스 | DATA-01 / DATA-02 | 분류 오류 수정, 공급원 관리 |
| 공지·정책 | 운영 공지 / 정책 버전 / 광고 운영(조건부) | COM-01~03 | 사용자 안내와 게시 정책 관리 |
| 권한·작업 이력 | 관리자 계정 / 작업·열람 이력 | SEC-01 / SEC-02 | 접근 통제와 변경 추적 |

일반 신고, 권리침해 요청, 개인정보 요청은 목록 UI를 재사용할 수 있으나 상태·권한·기한·완료 조건은 분리한다. 유출 대응은 제한된 담당자에게만 노출한다.

## 3. 공통 화면과 동작

### 3.1 공통 레이아웃

| 위치 | 구성 |
| --- | --- |
| 상단 | 서비스명, 운영/개발 환경 표시, 로그인한 관리자와 역할, 로그아웃 |
| 좌측 | 허용된 메뉴, 처리 대기 건수. 개별 목록과 동일한 집계 기준 사용 |
| 본문 상단 | 화면 제목, 현재 조회 조건, 마지막 갱신 시각, 새로고침, 허용된 주요 조치 |
| 목록 | 검색·필터, 결과 수, 정렬, 표, 페이지 이동 |
| 상세 | 식별 정보와 현재 상태, 업무별 탭, 근거·연결 항목, 처리 이력, 실행 버튼 |
| 변경 확인 | 대상과 개수, 변경 전후, 영향 범위, 복구 가능 여부, 사유, 최종 실행 |

초기 도메인은 애니로 고정 표시한다. 실제로 서비스하지 않는 영화·음악은 선택 가능한 운영 필터로 노출하지 않는다. 기간은 한국 시간으로 표시하고, 저장·집계 기준 시각과 구분한다.

### 3.2 조회·오류 표시

- 공통 필터는 기간·상태이며, 콘텐츠가 관련된 화면은 세부 주제·콘텐츠 유형을 추가한다. 화면 간 이동 시 기간과 관련 대상 필터를 유지한다.
- 목록의 빈 결과는 조회 성공 시에만 표시한다. 장애로 목록을 못 불러온 경우에는 오류와 재조회 버튼을 표시한다.
- 지표는 정상 수치 / 집계 중 / 수집 전 / 표본 부족 / 연결 전 / 집계 실패를 구분한다. 확인된 0건만 0으로 표시한다.
- 운영 데이터가 기본값이다. 개발·시연·테스트 데이터는 제외하고, 개발 환경에서만 명시적으로 포함해 볼 수 있게 한다.
- 조회 중이거나 다른 관리자의 변경으로 상태가 달라지면 실행 전에 최신 상태를 다시 확인한다. 오래된 화면의 조치가 새 상태를 덮어쓰지 않게 한다.

### 3.3 변경·재시도 공통 규칙

- 발행, 공개본 교체, 숨김, 삭제, 복구, 제재, 권한 변경, 정책 적용에는 대상·사유·실행자를 기록한다.
- 삭제·영구정지·일괄 작업은 재확인한다. 실제 적용할 대상과 불가 대상을 나눠 보여준다.
- 실행 요청 접수와 실제 완료를 구분한다. 백그라운드 작업이면 처리 중 표시 후 최종 성공·실패를 확인한다.
- 중복 클릭·통신 재시도로 같은 발행·제재·통지가 중복 생성되지 않게 한다.
- 여러 건 처리 중 일부만 실패하면 성공·실패 대상과 사유를 나눠 보여주며, 실패한 대상만 재시도한다.
- 오류 메시지에 인증 토큰, API 키, 원문 개인정보를 노출하지 않는다.

### 3.4 최소 권한 제안

PRD의 최고관리자·운영자·검수자·분석자 4개 고정 역할을 기준으로 한다. 정확한 작업별 권한은 출시 전 확정한다.

| 역할 | 기본 허용 범위 제안 | 기본 제한 |
| --- | --- | --- |
| 최고관리자 | 관리자 계정·고정 역할 지정, 중요 설정, 업무 권한 부여 | 민감정보도 업무 목적에 따른 열람 기록 적용 |
| 운영자 | 콘텐츠 노출 조치, 신고·제재, 공지, 수집 운영 | 관리자 권한 변경 불가. 개인정보 원문·유출 대응은 별도 지정 |
| 검수자 | 콘텐츠·근거 조회, 수정 초안, 재검수, 검토 결과 기록 | 회원 제재·권한 변경 불가. 공개본 교체·숨김은 허용 범위 별도 확정 |
| 분석자 | 집계와 마스킹된 운영 현황 조회 | 상태 변경과 개인 활동·대화 원문 열람 불가 |

화면에서 버튼을 숨기는 것과 별도로 서버에서 각 작업의 권한을 확인한다. 개인정보·권리침해 증빙·유출 대응의 상세 자료는 지정된 업무 담당자에게만 제공한다. 기존 소비자/크리에이터 가입 유형을 관리자 권한으로 사용하지 않는다.

## 4. 운영 현황

### ADM-01. 오늘의 운영 현황

**목적:** 운영자가 접속 후 먼저 처리할 작업을 고르고 해당 화면으로 이동한다.

| 화면 영역 | 보여줄 정보 | 가능한 조치 |
| --- | --- | --- |
| 오늘 처리할 일 | 검수 대기, 장기 미처리, 생성·발행 실패, 일반 신고 대기, 처리기한 임박 요청 | 카드 선택 시 해당 조건으로 목록 이동 |
| 공급 상태 | 세부 주제별 공개 콘텐츠 수, 최근 발행 시각, 최근 공급량, 콘텐츠가 없는 주제 | 콘텐츠·작업·소스 목록으로 이동 |
| 작업 상태 | 수집·생성·검수·발행 단계별 진행/실패 수, 챗봇 실패·장기 처리 중 | 실패 단계로 필터된 작업 상세 이동 |
| 서비스 지표 | 가입자, 이용 가능한 회원, 공개 콘텐츠, 반응·저장 현황. 활동·추천 성과 지표는 수집 준비 후 제공 | 기간 변경, 정의·집계 상태 확인 |
| 내 담당 업무 | 배정된 검수·신고·요청, 접수 시각, 다음 조치, 기한 | 해당 상세 화면으로 이동 |
| 최근 중요 변경 | 발행·숨김·정정·제재·정책 변경의 대상·담당자·시각 | 변경 이력 확인 |

- 기본 기간 제안: 오늘. 7일·30일·직접 선택 제공. 미처리 잔량은 선택 기간에 접수된 건수와 별도로 표시한다.
- 처리기한 임박 기준은 업무별 확정 정책을 사용한다. 기한이 정해지지 않은 항목은 경과 시간을 표시한다.
- 권한 없는 요청은 민감한 제목·대상자를 표시하지 않는다. 개인정보 업무 상세 진입은 별도 권한을 적용한다.
- 이 화면에서 대량 삭제·제재를 바로 실행하지 않는다. 조치 대상의 상세와 근거를 확인하는 경로로 연결한다.
- 완료 기준: 카드 수와 연결된 목록의 조건·결과가 일치하고, 최신 집계 시각을 확인할 수 있다.

근거: FR-801·802·406·407. 실패 작업·업무 잔량·최소 공급 경고는 1차 보완 제안이며 FR-815의 일부를 앞당긴다.

## 5. 콘텐츠

### CNT-01. 콘텐츠 목록

**목적:** 공개 콘텐츠와 검토할 생성물을 찾고, 검수·정정·노출 조치로 이동한다.

| 항목 | 구성 |
| --- | --- |
| 기본 탭 | 전체 / 검토 필요 / 게시 대기 / 공개 중 / 숨김·삭제 |
| 검색 | 콘텐츠 ID, 제목, 연결 작품명, 생성 작업 ID |
| 필터 | 생성일·발행일, 세부 주제, 유형, 검수 상태, 공개 상태, 검토 사유, 담당자 |
| 표 컬럼 | 썸네일, ID·제목, 유형·세부 주제, 검수 상태, 공개 상태, 검토 사유, 담당자, 최근 변경일 |
| 행 조치 | 상세 보기, 담당자 지정. 허용된 상태에서만 숨김·추천 제외 등 노출 조치 |
| 최소 일괄 조치 | 담당자 지정, 숨김, 추천 제외. 대상·변경 미리보기와 불가 사유 제공 |

일괄 영구삭제·일괄 본문 수정은 1차에서 제공하지 않는다. 검토 필요 탭에는 AI 검사 미통과, 출처·분류 불명, 사용자 신고로 재검토 중인 콘텐츠를 사유별로 구분해 모은다.

### CNT-02. 콘텐츠 상세·검수·정정

**화면 배치:** 상단은 ID·제목·유형·상태·담당자, 중앙은 소비자 화면 미리보기와 검수 근거, 하단은 처리 이력과 조치 영역이다.

| 탭/영역 | 보여줄 정보 | 가능한 조치 |
| --- | --- | --- |

| 검수 결과 | 검사 항목별 결과·근거·확신도, 실패 이유, 스포일러·연령 관련 확인 항목, 적용 검사 버전 | 문제 위치 확인, 보완 내용 입력, 재검수 요청, 검토 보류·종결 |
| 정정 초안 | 현재 공개본과 수정본의 제목·본문·카드·캡션·출처 차이 | 초안 저장, 일부 수정, 재생성 요청, 초안 폐기 |
| 노출 상태 | 피드·검색·추천·상세·챗봇 근거 사용 가능 여부, 제한 사유 | 숨김, 추천 제외, 논리 삭제, 복구 검토 |
| 관련 처리·이력 | 연결 신고·권리침해 요청, 생성 작업, 발행·수정·노출 변경 이력 | 사건·작업으로 이동, 변경 전후 확인 |

**조치별 동작**

| 조치 | 실행 조건 | 실행 후 결과 |
| --- | --- | --- |
| 수정 초안 저장 | 수정 권한, 변경 내용 존재 | 비공개 수정본 저장. 현재 공개본은 즉시 덮어쓰지 않음 |
| 재생성 요청 | 대상·수정 이유 지정, 같은 작업 중복 실행 없음 | 새 작업 ID와 초안 연결. 기존 공개본과 구분 |
| 재검수 | 필수 본문·출처·표시 정보 충족 | 검수 진행 상태와 결과 갱신. 미통과 시 발행 차단 |
| 게시 / 공개본 교체 | 필수 검사 통과, 차단 사유 없음, 해당 권한 | 공개 버전·발행 시각 기록, 관련 화면 반영 상태 확인 |
| 숨김 | 공개 대상, 사유 입력 | 소비자 접근 제한. 적용 중/완료/실패 표시 |
| 추천 제외 | 추천 제외 사유·범위 확인 | 콘텐츠 상세는 유지하고 추천 후보에서만 제외 |
| 논리 삭제 | 영향·복구 가능 여부 확인, 재확인 | 삭제 상태와 이력 기록. 사용자 저장 기록 자체를 임의로 삭제하지 않음 |
| 복구 | 다른 차단·삭제 요청 유무와 현재 정책 재확인 | 허용된 상태로만 복구. 복구와 재공개를 구분 |
| 검토 보류 | 추가 확인 사유·담당자·다음 확인시점 입력 | 미완료 업무로 유지하고 다시 확인할 시점에 표시 |
| 검토 종결 | 사용하지 않음·검토 완료 등 최종 결론과 사유 입력 | 검토 업무 종료. 콘텐츠 삭제 여부는 별도 조치 |

**검수 상태와 공개 상태를 분리한다.**

- 검수 상태 제안: 검사 전 → 검사 중 → 통과 또는 사람 검토 필요 → 보완 후 재검수 / 보류 / 종결.
- 보류는 임시 대기이며 미완료 잔량에 포함한다. 담당자와 다음 확인시점 없이 보류로 닫을 수 없게 한다.
- 공개 상태 제안: 미게시 → 게시 처리 중 → 공개 / 게시 실패. 이후 숨김·논리 삭제·복구 검토를 별도 기록한다.
- 자동 검수 통과 후 자동 게시할 콘텐츠 유형과 수동 게시할 유형은 정책으로 확정한다. 전체 사람 승인 단계를 추가하지 않는다.
- 일반 정정 중에는 기존 공개본을 유지할 수 있다. 유해·권리침해 등 문제가 있으면 담당자가 별도 숨김 조치를 수행한다.
- 필수 검사 실패를 무시하는 강제 발행 버튼은 기본 제공하지 않는다. 오판정 정정은 근거와 이력을 남기고 다시 검사한다.
- 숨김·삭제된 콘텐츠는 피드·검색·추천·직접 링크·새 챗봇 근거 조회에서 일관되게 제한한다. 저장함에는 이용 불가 상태를 표시한다. 캐시 반영 실패를 완료로 처리하지 않는다.
- 복구는 권리침해 차단·다른 운영 제한·개인정보 삭제 처리까지 해제하지 않는다. 이전 버전을 사용할 때도 같은 확인을 적용한다.
- 이미지 이용 근거·스포일러 검토 항목·공개본/수정본 분리는 보완 제안이다. 점수 기준과 항목별 발행 차단 조건은 결정이 필요하다.

완료 기준: 미통과 글이 공개되지 않고, 수정본과 공개본이 구분되며, 노출 조치의 실제 반영과 변경 이력을 확인할 수 있다.

근거: FR-302·304·308·309·312·313·808·809·813·814·817·913. 본문·카드 정정, 공개본 분리, 최소 추천 제외는 1차 보완 제안.

## 6. AI·수집 작업

### OPS-01. 수집·생성 작업 목록과 상세

**목적:** 생성과 발행 중 어디에서 문제가 생겼는지 확인하고 안전하게 재처리한다.

| 항목 | 구성 |
| --- | --- |
| 목록 필터 | 기간, 작업 종류, 세부 주제, 콘텐츠 유형, 작업 상태, 실패 단계, 소스 |
| 목록 컬럼 | 작업 ID, 종류·유형, 상태, 현재/실패 단계, 시작·종료시각, 소요시간, 시도 횟수, 연결 콘텐츠 |
| 상세 상단 | 실행 ID, 입력 대상, 적용 모델·프롬프트·검사 버전, 실행 원인, 생성/발행 결과 |
| 단계별 상세 | 실제 수행한 수집·소재 선정·이미지 수집·작성·조립·검수·발행 단계의 시작/종료·결과·실패 원인 |
| 결과 | 수집/제외 건수와 사유, 생성 초안, 검수 결과, 발행 콘텐츠 ID, 원본 실행과 재실행 관계 |
| 사용량 | 계측된 호출·토큰·비용. 계측 전은 수집 전 표시 |

| 조치 | 동작과 제한 |
| --- | --- |
| 실패 작업 재실행 | 마지막 성공 결과를 재사용할 수 있는 단계만 재개. 미지원 시 전체 재실행임을 알리고 새 작업으로 연결 |
| 게시 실패 재시도 | 생성 성공 초안을 재사용하고 발행만 재시도. 동일 초안의 중복 게시 방지 |
| 대기 작업 취소 | 아직 실행 전인 작업을 취소하고 사유 기록 |
| 진행 작업 중지 요청 | 중지 지원 시 제공. 요청 중과 실제 중지 완료를 구분하고, 미지원이면 실행 버튼을 제공하지 않음 |
| 신규 실행 일시 중지 | 운영 권한으로 소스·유형별 향후 작업을 중지. 이미 진행 중인 작업에 대한 영향 별도 안내 |
| 콘텐츠 검토로 이동 | 검수 미통과는 콘텐츠 처리함으로, 발행 성공은 공개 콘텐츠 상세로 연결 |

작업 상태 제안: 대기 / 실행 중 / 성공 / 실패 / 취소 요청 / 취소 완료. 검수 미통과는 기술적 실행 실패와 구분한다. 생성 성공·게시 실패를 별도로 표시한다.

실행기의 중지 확인 후에만 취소 완료로 표시한다. 중지 실패·시간 초과는 실제 실행 상태와 함께 표시하고, 작업이 먼저 종료되면 실제 성공·실패 결과를 유지한다. 중지 완료 이후 추가 발행이 발생하지 않아야 하며, 이미 발행된 결과는 별도 콘텐츠 노출 조치로 연결한다.

최대 재시도 횟수, 작업 시간 초과 기준, 신규 실행 중지 권한은 결정 필요다. 재시도가 추가 비용을 발생시킬 수 있음을 해당 확인 화면에 표시한다.

완료 기준: 실행→초안→콘텐츠 관계가 추적되고, 재시도 후 최종 상태가 갱신되며, 같은 콘텐츠가 중복 게시되지 않는다. 중지는 요청 접수와 실행기의 실제 중지 결과를 구분한다.

근거: FR-301·312·313·314. 작업 조회·재시도·중지 화면은 1차 보완 제안. 기존 localhost 개발용 Agent API는 운영 관리자 API로 그대로 사용하지 않는다.

### OPS-02. 챗봇 운영

**목적:** 서비스 답변의 실패와 근거 문제를 확인한다. 기본 화면은 집계와 마스킹된 오류 정보 중심이다.

| 영역 | 보여줄 정보 | 가능한 조치 |
| --- | --- | --- |
| 요약 | 요청 수, 기술적 실패율, 장기 처리 중, 응답시간, 근거 없음 비율, 사용량·비용의 수집 상태 | 기간·상태·유형 필터 |
| 요청 목록 | 요청 ID, 비식별 사용자 ID, 시각, 상태, 소요시간, 근거 수, 오류 유형 | 요청 상세 조회 |
| 상세 | 입력·답변의 마스킹본, 실패 단계, 참조 콘텐츠와 당시 버전, 검사 결과, 모델·프롬프트 버전 | 콘텐츠 검토·운영 사건으로 연결 |
| 제한 열람 | 지정 담당자에게만 필요한 범위의 원문 | 목적 입력 후 열람, 열람 이력 저장 |
| 점검용 테스트 | 테스트 질문, 선택한 콘텐츠와 설정, 테스트 답변·근거 | 별도 테스트 실행. 실사용 대화와 통계에 섞지 않음 |

- 근거 없음·분야 밖 안내는 시스템 오류와 구분한다. 정상적인 답변 제한을 오류율에 합산하지 않는다.
- 1차에는 사용자의 과거 답변을 관리자 화면에서 덮어쓰거나 무조건 재전송하지 않는다.
- 실사용 요청 재처리는 별도 서비스가 구현되고 중복·전달 정책이 정해진 경우에만 제공한다. 테스트 실행과 같은 버튼으로 취급하지 않는다.
- 숨김·삭제된 콘텐츠를 새 답변 근거로 재사용하지 않으며, 과거 답변에서의 연결 표시 방식은 정책으로 정한다.
- 대화 보관·삭제와 장기 기억 기본값을 먼저 확정하고, 만료된 원문을 운영 화면에 계속 보관하지 않는다.

완료 기준: 실패·근거 없음·정상 응답을 구분하고, 문제의 참조 콘텐츠를 찾아 조치할 수 있으며, 테스트가 실사용 대화에 영향을 주지 않는다.

근거: FR-501·607·608·610·1202. 운영 집계·제한 열람·점검용 테스트는 1차 보완 제안.

## 7. 회원·요청 처리

### USR-01. 회원 목록과 상세

**목적:** 필요한 회원을 찾고 현재 이용 상태, 동의, 관련 요청을 확인한다.

| 항목 | 구성 |
| --- | --- |
| 검색·필터 | 사용자 ID, 닉네임, 허용된 이메일 검색, 가입 기간, 이용 상태, 온보딩 상태, 선택 주제 |
| 목록 컬럼 | 사용자 ID, 닉네임, 마스킹 이메일, 가입일, 이용 상태, 온보딩 완료 여부, 열린 요청 수 |
| 기본 정보 탭 | 프로필, 가입·온보딩 정보, 계정 상태. 생년월일은 목적에 맞는 연령 확인 결과 또는 연령대로 제한 |
| 동의 탭 | 항목별 동의 여부·시각·정책 버전, 철회 이력 |
| 요청·조치 탭 | 신고, 제재, 이의, 개인정보 요청, 처리 담당자와 현재 상태 |
| 활동 요약 탭 | 필요한 범위의 반응·저장 집계. 개인 읽기·대화 원문의 무제한 열람은 기본 제공하지 않음 |
| 가능한 조치 | 제재 기록 생성, 기존 제재 해제·완화 화면 이동, 요청 접수·연결, 제한된 정보 열람 |

- 운영자가 사용자의 O/X·좋아요·저장 내역을 임의로 바꾸거나 동의를 대신 켜는 기능은 제공하지 않는다.
- 계정 상태 변경과 개인정보 삭제는 별도 업무다. 회원 상세의 단일 삭제 버튼으로 모든 데이터를 지우지 않는다.
- 경고는 이용 가능한 계정에 경고 이력을 남기는 방식으로 설계한다. 경고 자체가 로그인 차단으로 이어지지 않아야 한다.
- 제재 중이더라도 이의 제기와 필요한 요청을 제출할 경로를 제공한다. 일반 로그인 차단과 별도 접근 경로를 설계해야 한다.

완료 기준: 동일 회원의 요청과 조치가 연결되며, 권한 없는 정보는 목록·상세·검색 결과에서 노출되지 않는다.

근거: FR-203·204·804·805·1204. 민감정보 최소 표시와 제재 완료 흐름은 보완 제안.

### CASE-01. 일반 신고 처리함

**목적:** 콘텐츠 신고를 접수하고 검토·조치·신고자 안내까지 끝낸다. 단순 문의를 함께 접수한다면 별도 유형으로 분류한다.

| 항목 | 구성 |
| --- | --- |
| 탭·필터 | 신규 / 검토 중 / 조치 중 / 안내 필요 / 완료. 신고 사유, 접수 기간, 대상, 담당자, 긴급 표시 |
| 목록 컬럼 | 사건 ID, 대상 콘텐츠, 신고 사유, 신고 건수, 최초/최근 접수, 담당자, 경과 시간, 처리 상태 |
| 상세 | 원래 접수된 신고별 내용·시각, 신고 당시 콘텐츠 버전, 현재 콘텐츠, AI 판정 근거, 관련 사건·조치 |
| 가능한 조치 | 담당자 지정, 수동 긴급 표시, 중복 신고 연결·분리, 콘텐츠 검토로 이동, 조치/조치 없음 결정, 결과 안내 |

- 같은 콘텐츠의 신고를 사건 단위로 묶되 원래 접수 기록과 신고자별 안내 상태를 보존한다. 다른 사유를 합쳐 없애지 않는다.
- 우선순위 자동 점수 대신 1차는 수동 긴급 표시와 접수순 정렬을 제공한다.
- 신고 종결과 콘텐츠 숨김·회원 제재는 별도 기록으로 연결한다. 신고를 완료했다고 자동으로 콘텐츠를 삭제하지 않는다.
- 플랫폼 AI 생성물 오류는 제작·정정 업무로 연결한다. 신고자가 콘텐츠 작성자라는 가정을 하지 않는다.
- 사용자 접수 화면/API와 연결되어야 한다. 관리자 내부 접수 건은 접수 경로와 기록자를 표시한다.

상태 제안: 접수 → 검토 중 → 조치 중 또는 조치 없음 결정 → 결과 안내 대기 → 완료. 조치 실패·안내 실패는 재처리 대상으로 남긴다.

완료 기준: 결론·근거·실제 조치 결과가 기록되고, 신고자에게 결과가 전달되거나 전달 불가 사유가 기록된다. 조치 없음도 결과 안내한다.

근거: FR-710·808·810·811·812·817. 최소 결과 안내와 수동 긴급 표시는 1차 보완 제안.

### CASE-02. 제재·이의 처리

**목적:** 제재 시작뿐 아니라 만료·해제·이의 결과까지 관리한다. 회원 상세에서 진입할 수 있고, 별도 목록에서 만료·이의 대기 건을 확인한다.

| 항목 | 구성 |
| --- | --- |
| 목록 | 제재 ID, 회원, 적용 범위, 경고/일시정지/영구정지, 시작·종료, 유효 상태, 관련 이의, 담당자 |
| 상세 | 적용 사유·근거·정책, 실제 제한되는 기능, 원래 사건, 변경 이력, 사용자 안내, 이의 내용 |
| 제재 조치 | 경고 등록, 기간제 제한, 영구정지, 수동 해제, 범위·기간 완화, 사유 정정 기록 |
| 이의 조치 | 접수, 담당자 지정, 추가 자료 요청, 수용/일부 수용/기각, 기존 제재 변경, 결과 안내 |

- 일시정지는 시작·종료시각을 필수로 받고 만료 후 해제를 확인한다. 해제 실패는 운영 현황에 표시한다.
- 여러 제재가 겹치면 하나를 해제해도 남은 제재가 유지되는지 확인한다.
- 영구정지에는 대상·영향·재확인이 필요하다. 계정 영구정지와 개인정보 영구삭제는 같은 작업이 아니다.
- 잘못된 경고도 삭제해 흔적을 없애기보다 취소 이력으로 남긴다.
- 정식 이의 전용 사용자 화면을 미루는 경우에도 정지 사용자가 접근할 대체 접수 경로와 관리자의 등록·검토 화면은 마련한다.

완료 기준: 제재의 실제 제한·해제가 기록과 일치하고, 이의 수용 시 원래 제재까지 변경된 후 결과 안내가 완료된다.

근거: FR-805·807·816. 만료·해제·최소 이의 처리의 1차 제공은 보완 제안.

### CASE-03. 권리침해 요청 처리함

**목적:** 권리침해 소명과 임시조치를 일반 신고와 분리해 처리한다.

| 항목 | 구성 |
| --- | --- |
| 목록 | 요청 ID, 대상 콘텐츠, 요청 유형, 접수 시각, 증빙 상태, 담당자, 조치 상태, 검토·차단 기한 |
| 상세 | 요청자와 대리 여부, 소명 자료, 대상 URL·버전, 요구 조치, 기존 조치, 통지 이력 |
| 가능한 조치 | 담당자 지정, 보완 요청, 접근 차단 요청, 검토 결과 기록, 차단 유지·해제 검토, 대상별 통지 기록 |
| 후속 확인 | 피드·상세·검색·추천·챗봇 근거에서 차단 반영, 연결 콘텐츠 영향, 기한 도래 후 검토 필요 여부 |

상태 제안: 접수 / 자료 보완 중 / 검토 중 / 차단 적용 중 / 임시 차단 / 해제 검토 / 종결. 기한이 지났다는 이유만으로 다른 제한까지 해제해 재공개하지 않는다.

- 비회원 권리자의 접수도 등록·연결할 수 있게 한다. 접수·본인 및 권한 확인 방법은 별도 확정한다.
- 증빙 자료와 연락처는 지정 담당자에게만 제공하고 열람을 기록한다.
- 차단·해제에는 사유와 담당자를 기록한다. 다른 차단이 남아 있으면 일반 복구로 공개되지 않게 한다.
- PRD FR-818-4에 기재된 판단 곤란 시 임시 차단 상한은 최대 30일이다. 이는 기존 요구의 인용이며 법적 적합성 검증 결과가 아니다. 화면에는 시작·만료시각과 다음 검토일을 표시한다.
- 권장 운영 규칙: 만료 전에 담당자가 후속 결정을 하고, 기한 도래까지 해제 또는 별도 근거가 있는 확정 조치로 전환한다. 판단 지연만으로 같은 임시 차단을 무기한 연장하지 않는다. 다른 차단이 남아 있으면 그 근거와 상태를 별도로 표시한다.
- 그 밖의 접수·통지 기한과 만료 처리 책임은 확정된 운영 정책을 따른다. 이 문서에서 새로운 법적 기한을 판단하지 않는다.
- 플랫폼 제작 콘텐츠에서는 내부 제작 담당과 요청자에게 필요한 안내를 구분한다. 외부 작성자가 있다고 가정하지 않는다.

완료 기준: 결론과 실제 접근 상태, 필요한 통지 결과가 일치하고 미완료 후속 작업이 남아 있지 않는다.

근거: FR-818·204. 기한·담당자·차단 반영·종결 조건은 화면 수준 보완.

### CASE-04. 개인정보·탈퇴 요청 처리함

**목적:** 정보 열람·정정·삭제·처리정지·동의 철회·탈퇴·복구 요청의 실행 결과를 확인한다.

| 항목 | 구성 |
| --- | --- |
| 목록 | 요청 ID, 회원 ID, 요청 유형, 접수 경로, 확인 상태, 요청 범위, 접수·처리 예정일, 상태·담당자 |
| 상세 | 요청 내용과 본인 확인 상태, 적용 정책, 처리 대상 항목·저장소, 유지가 필요한 항목의 근거, 사용자 안내 |
| 진행 확인 | 계정·활동 기록·추천 사용·대화/장기 기억·캐시 등 실제 대상별 대기/완료/실패 |
| 가능한 조치 | 보완 요청, 처리 범위 확인, 승인된 절차 실행, 실패 대상 재처리, 결과 안내, 허용된 유예 탈퇴 복구 |

상태 제안: 접수 → 확인 중 → 처리 대기 → 처리 중 → 처리 완료 → 결과 안내 완료. 보완 필요·일부 실패를 별도로 표시한다.

- 즉시 삭제와 유예 탈퇴를 구분한다. 유예 기간은 확정 정책을 적용하고 화면에 예정일을 표시한다.
- 영구삭제가 완료된 정보는 복구 가능으로 표시하지 않는다. 유예 중 복구도 이미 삭제된 데이터를 복원한다고 보장하지 않는다.
- 처리정지는 관련 정보를 보관하되 추천 계산에서 제외하는 작업이다. 정보 삭제와 구분한다.
- 부분 실패 시 전체 삭제 완료로 처리하지 않는다. 삭제 대상 원문을 감사 로그에 복사해 남기지 않고 요청·처리 결과와 필요한 식별 정보만 기록한다.
- 보관 예외·확인 절차·응답 기한은 확정 정책을 참조한다. 임의 예외 처리를 허용하지 않는다.

완료 기준: 요청 범위별 실제 처리 결과와 안내가 확인되고, 추천 사용 중지·대화 삭제 같은 후속 시스템에도 반영된다.

근거: FR-205·206·608·1201·1202·1204. 대상별 완료·실패 재처리 화면은 1차 보완 제안.

### CASE-05. 개인정보 유출 대응 기록

**목적:** 감지된 정황에 대해 담당자가 대응·통지·후속 조치 기록을 관리한다. 1차에 별도 보안 탐지 시스템을 만드는 범위는 아니다.

| 목록 필터 | 활성 여부, 수집 방식, 최근 성공/실패, 이용 조건 확인 상태 |
| 목록 컬럼 | 소스명·주소, API/RSS/웹 구분, 수집 상태, 최근 시도·성공, 실패 수, 최근 수집 건수 |
| 상세 | 허용 자료·언어·형식, 이용 근거·확인일·담당자, 수집 주기, 제외 조건, 연결 작업·콘텐츠 |
| 가능한 조치 | 기존 소스 활성/중지, 실패 작업 조회·재실행, 이용 기준 기록 갱신, 변경 이력 조회 |

- 새 소스 등록·접속 정보 변경은 지정된 운영 절차로 수행한다. API 키·자격증명 원문은 관리자 화면에 표시하지 않는다.
- 소스 중지는 앞으로의 수집에 적용한다. 이미 게시된 콘텐츠는 별도로 검토하고 필요 시 콘텐츠 메뉴에서 조치한다.
- 이용 조건이 미확정인 자료는 확인 상태를 분명히 표시한다. 이용 가능 여부를 자동으로 확정하는 기능은 제공하지 않는다.
- 수집 제외와 수집 실패를 구분한다. 언어·파일형식 등 조건에 따른 제외를 장애로 집계하지 않는다.

완료 기준: 소스별 성공·실패 원인을 찾을 수 있고, 중지 상태가 실제 신규 수집에 반영된다.

근거: FR-301·308·314·1203. 소스 운영 화면은 1차 보완 제안.

## 9. 공지·정책

### COM-01. 운영 공지

**목적:** 공지의 내용·대상·노출과 전달 결과를 관리한다.

| 화면 영역 | 구성 |
| --- | --- |
| 목록 | 공지 ID, 제목, 유형, 대상, 초안/게시 중/종료, 게시·종료시각, 작성자, 전달 상태 |
| 작성·수정 | 제목, 본문, 연결 화면, 공지 유형, 전체/세부 주제 대상, 노출 기간 |
| 미리보기 | 사용자 알림함·공지 상세에 표시될 내용, 대상 조건·예상 대상 수 |
| 게시 결과 | 게시 완료 여부, 알림함 등록 결과. 푸시 연동 시 발송·실패·수신설정 제외 수를 별도 표시 |
| 가능한 조치 | 초안 저장, 미리보기, 게시, 게시 종료, 변경 이력 확인, 실패한 전달만 재시도 |

- 1차 기본 경로는 운영 공지 게시와 서비스 내 알림함 연결이다. 예약 게시·외부 푸시는 해당 발송 서비스가 구현됐을 때 제공한다.
- 게시 완료와 알림 전달 완료를 구분한다. 푸시가 미구현이면 발송 완료로 표시하지 않는다.
- 일반 운영 공지와 별도 절차의 필수 통지를 구분한다. 사용자가 끈 알림을 일반 공지에서 우회할 수 있는 버튼은 제공하지 않는다.
- 필수 공지 여부와 수신 거부 적용 범위는 정책 확정 전 임의로 선택하지 못하게 한다.
- 이미 전달된 공지의 수정은 기존 전달 내용을 몰래 교체하지 않는다. 변경 내용을 기록하고 재안내 필요 여부를 확인한다.
- 대상 선택은 개인 활동·대화 내용을 사용하는 자유 검색이 아니라 승인된 전체/세부 주제 조건으로 제한한다.

완료 기준: 게시한 내용과 대상이 미리보기와 일치하고, 게시·전달·실패 결과가 구분되며 재시도 시 중복 안내하지 않는다.

근거: FR-719·712. 미리보기·전달 상태·이력은 보완 제안.

### COM-02. 정책 버전

**목적:** 사용자에게 적용되는 정책과 동의 문구의 버전을 관리한다.

| 영역 | 보여줄 정보 | 가능한 조치 |
| --- | --- | --- |
| 정책 목록 | 정책 종류, 버전, 초안/시행 중/종료, 시행일, 작성자 | 현재 버전·이전 버전 확인 |
| 편집·비교 | 새 버전 문안, 현재 문안과 변경점, 사용자 안내, 재동의 필요 여부 검토값 | 새 초안 작성·저장, 미리보기, 확정 절차 후 적용 |
| 적용 결과 | 적용된 버전, 적용 시각, 관련 공지·동의 항목 | 변경·적용 이력 확인 |

- 시행 중인 문안을 덮어쓰지 않고 새 버전으로 만든다. 기존 동의 이력은 당시 버전에 연결해 보존한다.
- 1차는 권한 있는 담당자의 수동 적용을 기준으로 한다. 미래 시행일 자동 적용은 예약 기능이 준비된 경우에만 제공한다.
- 재동의 필요 여부와 동의 항목 분류는 관리자가 임의 추정하지 않고 확정된 정책 검토 결과를 입력한다.
- 잘못 적용된 버전의 조치는 기존 기록 삭제가 아니라 정정 버전과 안내로 추적한다.

완료 기준: 현재 사용자 안내에는 시행 중인 문안·버전이 표시되고, 각 동의 기록은 동의 당시의 문안·버전에 연결된다. 재동의 대상의 미동의 상태를 구분하며 초안이 실수로 시행되지 않는다.

근거: FR-1201·1202·1204. 정책 버전 운영 화면은 보완 제안.

### COM-03. 광고 운영 — 광고를 1차에 활성화할 경우

**목적:** 서비스가 통제할 수 있는 광고 노출 범위와 문제 광고를 관리한다.

| 영역 | 구성 |
| --- | --- |
| 목록·상태 | 광고 지면, 연동 공급자, 노출 사용 여부, 광고 표시 상태, 연결 문제 신고 |
| 상세 | 광고·소재 식별 정보가 제공되는 범위, 적용 주제, 표시 미리보기, 노출 조건, 연동 오류 |
| 가능한 조치 | 지면 노출 중지·재개, 공급자가 지원하는 소재 차단, 문제 신고 연결 |

- 공급자가 지원하지 않는 개별 소재·주제 통제를 제공하는 것처럼 표시하지 않는다. 소재 차단이 불가하면 지면 중지를 대안으로 제공한다.
- 광고 문구가 표시되지 않거나 정해진 노출 조건을 만족하지 못하면 노출하지 않는 동작을 검증한다.
- 캠페인 생성·매출 정산·광고 최적화는 1차 범위에서 제외한다. 광고 미출시 시 메뉴 자체를 숨긴다.

완료 기준: 관리자 중지 조치가 실제 노출에 반영되고, 서비스가 지원하는 통제 범위를 확인할 수 있다.

근거: FR-1101~1103. 광고 출시 여부·공급자 제어 가능 범위는 결정 필요.

## 10. 권한·작업 이력

### SEC-01. 관리자 계정

**목적:** 관리 권한을 가진 사람과 허용 범위를 확인하고 접근을 회수한다.

| 항목 | 구성 |
| --- | --- |
| 목록 | 관리자 ID·이름, 고정 역할, 활성 상태, 민감 업무 권한, 최근 로그인 시각, 권한 변경일 |
| 상세 | 허용 메뉴·조치, 담당 업무, 권한 부여·변경 이력 |
| 최소 조치 | 최고관리자의 승인된 계정 등록/활성화, 고정 역할 지정·변경, 접근 비활성화 |

- 계정 생성·초대는 서비스의 인증 방식에 맞는 통제된 절차를 사용한다. 일반 가입만으로 관리자 권한을 얻지 못한다.
- 본인의 권한을 스스로 올릴 수 없고, 마지막 활성 최고관리자를 제거하지 못하게 한다.
- 비활성화 시 기존 관리자 세션과 권한 캐시에도 회수가 반영되어야 한다.
- 민감 업무 권한은 역할과 별도로 명시한다. 권한 변경 전후와 이유를 기록한다.
- 임의 역할 생성·세밀한 권한 편집기는 후속 범위로 둔다. 초기 관리자 등록을 별도 운영 절차로 제공하더라도 화면의 계정 목록과 서버 권한은 일치해야 한다.

완료 기준: 부여·회수한 권한이 실제 화면과 변경 API에 적용되고, 회수된 세션으로 계속 작업할 수 없다.

근거: FR-007·203·204. 최소 권한 부여·회수의 1차 적용 제안. 고급 역할 관리 전체를 1차로 앞당기는 것은 아님.

### SEC-02. 작업·민감정보 열람 이력

**목적:** 누가 무엇을 왜 바꿨는지, 어떤 민감정보를 열람했는지 확인한다.

| 항목 | 구성 |
| --- | --- |
| 탭 | 상태 변경 작업 / 민감정보 열람 |
| 필터 | 기간, 관리자, 대상 종류·ID, 조치 종류, 성공/실패, 연결 사건 |
| 목록 | 시각, 관리자·당시 역할, 대상, 작업, 사유, 결과, 연결 작업·사건 ID |
| 상세 | 변경 전후, 실제 적용 결과, 실패 사유, 확인 절차, 관련 사건·작업으로 이동 |
| 가능한 조치 | 조회·검색. 복구가 필요하면 대상 상세로 이동해 현재 권한·제한을 다시 확인 |

- 이력 화면에서 기록을 수정·삭제하거나 권한 확인 없이 변경을 되돌리는 기능은 제공하지 않는다.
- 민감정보 원문을 변경 로그에 중복 보관하지 않는다. 필요한 항목명·처리 결과와 제한된 식별 정보를 남긴다.
- 열람 이력 자체도 권한을 제한한다. 1차는 화면 조회 중심이며 전체 로그 다운로드는 기본 제공하지 않는다.

완료 기준: 중요 조치의 대상·사유·담당자·변경 전후·실제 결과를 추적할 수 있고, 일반 관리 작업으로 기록을 덮어쓸 수 없다.

근거: FR-203·204·816.

## 12. 지표 정의와 데이터 준비

### 12.1 기본 지표 정의 제안

| 지표 | 정의 제안 | 주의사항 |
| --- | --- | --- |
| 검수 대기 잔량 | 현재 미완료인 검토 대상 콘텐츠 수 | 검사 시도 횟수와 콘텐츠 수를 구분 |
| 생성 작업 실패율 | 기간 내 성공 또는 기술적 실패로 종료된 생성 실행 중 기술적 실패 실행 비율 | 취소·진행 중 제외. 검수 미통과는 별도 지표. 재시도 실행 포함 여부 표시 |
| 발행 실패 잔량 | 유효한 생성 결과가 있고, 마지막 발행 시도가 실패한 뒤 아직 해결되지 않은 고유 발행 대상 수 | 동일 대상의 재시도 횟수와 구분. 정상 게시 대기·검수 보류·종결·재시도 진행 중 제외. 생성 실패에 합산하지 않음 |
| 공개 콘텐츠 수 | 현재 소비자가 접근 가능한 콘텐츠 수 | 숨김·삭제·권리침해 차단 제외. 추천 제외는 별도 구분 |
| 세부 주제 공급량 | 해당 기간에 새로 공개된 고유 콘텐츠 수 | 같은 콘텐츠의 재시도·정정 게시를 신규 공급으로 중복 집계하지 않음 |
