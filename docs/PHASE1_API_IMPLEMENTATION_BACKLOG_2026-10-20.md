# 1차 비관리자 API 구현 우선순위와 작업 목록

기준일: 2026-10-20. [PRD API 대조표](C:/Users/USER/me_nu/docs/PRD_API_GAP_ANALYSIS_2026-10-20.md)를 실행 가능한 작업 단위로 정리했다.

**2026-10-20 사용자 확정:** 최신 온보딩 UI는 Q1과 Q2에서 각각 **정확히 1개씩** 선택한다. 기존 최소 5개 선택 규칙을 대체하며 선택 개수는 더 이상 미정 사항이 아니다. 당시 선택 기준만 구현하라는 요청에 따라 독립 검증 모델 `OnboardingAnswers`를 추가했다.

**온보딩 완료 경로 변경 기록:** 사용자 요청으로 API-004의 로컬 경로를 `POST /api/v1/onboarding/complete`로 변경했다. 이 경로 변경 단계에서는 기존 요청·응답·저장 로직을 유지했다.

**2026-10-21 저장 계약 반영:** 후속 확정에 따라 기존 온보딩 `subtopicIds` 입력·세부 관심사 저장을 제거하고 필수 `answers: {q1,q2}`로 대체했다. 각 답변은 해당 질문의 허용 문자열 1개이며 기존 닉네임·생년월일·`accountType=user`·동의·Topic 입력은 유지한다. 답변은 `tap`별 `onboarding_answers`에 저장하며 추가 마이그레이션은 `c0e5f3b8a124`다. 실제 DB 적용 상태는 별도 검증한다. 응답은 저장한 `answers`와 `activeTopic.subtopicIds=[]`를 반환한다. Q2는 알림 수신 동의가 아니며 기존 세부 관심사 테이블·데이터·별도 구독 API는 유지한다. 프론트는 수정하지 않았으므로 호출 경로·입출력 타입과 화면 연결은 후속 작업이다.

**2026-10-21 온보딩 프로필 이미지 제외:** 사용자가 온보딩에서 프로필 이미지를 받지 않기로 확정하여 API-004 요청의 `profileImageId`와 이미지 미지원 오류 분기를 제거했다. 해당 필드는 `null`을 포함해 전송하면 추가 필드 검증으로 422 `VALIDATION_ERROR`를 반환하므로 요청에서 생략한다. DB 스키마·기존 이미지 데이터는 변경하지 않으며 추가 마이그레이션은 필요하지 않다. 이번 범위는 온보딩 API에 한정하며 별도 프로필 수정 API·T09 업로드 백로그 및 프론트는 변경하지 않는다.

**2026-10-21 로컬 적용·검증:** 카카오 테스트용 `me_nu_oauth_local`에 `c0e5f3b8a124`를 적용했다. 원본 `me_nu`는 `e7a4c2d9b812`로 유지하며 배포 DB는 변경하지 않았다. 관련 자동 테스트 126개를 검증했다(초기 120개 통과, 테스트 회원 fixture 보완 후 나머지 6개 통과). 실제 PostgreSQL에서도 온보딩 서비스의 답변 저장·빈 구독 목록·CHECK/NOT NULL을 확인하고 임시 검증 행은 롤백했다. 기존 계정은 보존했으며 수동 테스트를 위해 로컬 테스트용 약관 4개와 `anime` Topic을 추가했다. 로컬 Swagger 요청에서 필수 `answers`와 `subtopicIds` 제거를 확인했다. 프론트 연결·배포·커밋·푸시는 수행하지 않았다.

**현재 PRD 기준으로 선정한 1차 대상은 63개 API다. 기존 28개를 유지·보완하고, 없는 35개를 신규 구현한다.** 이 수는 이번 범위 해석으로 선정한 계약 수이며 공식 PRD의 확정 API 개수나 미완료 기능 개수는 아니다. 차수·범위·정책 확인이 필요한 6개와 후속 3개는 분리했다.

## 1. 범위와 우선순위 기준

- 기준: [2026-10-19 수정 PRD V1.0 사본](https://docs.google.com/spreadsheets/d/1qzCRxMw6RndRQznNr5tqDdj1PXZ9i7uE1rxZtsbvdO4/edit), [API 명세 V1.3](https://app.notion.com/p/3f704c45a9618146b3def322d33c646f), 로컬 `main 8df21b9`. PRD 원본 접근 제한으로 사본 기준이라는 이전 대조의 한계는 유지된다.
- 관리자 전용 `/api/v1/admin/*`, 크리에이터·채널·DM, 개발용·상태 확인 API는 제외한다.
- 사용자 탈퇴·개인정보 요청·신고·권리침해는 포함한다. 관리자 화면을 만들지 않아도 사용자 접수와 처리 결과 제공은 필요하다.
- 1차는 애니 중심이다. 최초 분야/세부 주제 조회와 필터는 필요하므로 API-017~019·021·025를 유지한다. 복수 분야 추가/삭제 및 구독 편집의 차수는 별개다.
- **P0/P1/P2는 모두 1차 안의 구현 우선순위다. P2도 1차 출시 전 완료 대상이며 2차 개발을 뜻하지 않는다.**
- **P0:** 공통 계약과 정식 가입처럼 후속 작업을 막는 기반.
- **P1:** 콘텐츠 소비·추천·AI 및 사용자 권리·신고의 핵심 기능.
- **P2:** 계정 편집·알림·광고의 남은 1차 범위. 선행 계약이 준비되면 P1과 병렬 진행 가능.
- API 번호를 새로 만들지 않는다. 캐러셀·사유 입력·AI 결과 타입은 기존 API 확장 후보로 두고, 새 endpoint가 필요하면 별도 계약을 확정한다.

### T01 공통 계약 정합화

- [x] 요청/응답·FE 타입을 `accountType=user`에 맞추고 회원 유형을 DB 컬럼에서 분리한다. ERD V1.1에 없는 `signup_channel`을 제거하는 마이그레이션을 준비한다. 실제 DB 적용은 보류한다.

- [ ] PRD의 30일 로그인 유지와 현재 기본 30분 세션을 맞출 정책을 정한다. 일반 로그인 유지와 탈퇴용 재인증 유효시간은 분리한다.

2026-10-20 반영: 온보딩과 개발용 가입·데모 계정은 `user`를 사용하고, 소비자/크리에이터 선택 UI는 일반 회원 시작으로 정리했다. 질문은 trim 후 Unicode 코드 포인트 기준 최대 500자로 서버·UI·API·mock에서 검증한다. 정책·대화 세션·Swagger 예시에 같은 AI 안내를 제공하고, 홈·상세 답변 화면에도 세션의 안내를 표시한다. 운영공지에만 목록·미읽음 수·읽음 처리를 적용한다. 당시 코드 수정에서는 기존 서버의 세부 주제 최소 1개, 기존 온보딩 UI 5개, 세션 기본 30분을 변경하지 않았다. 이후 확정된 Q1·Q2 각각 1개 저장 계약은 위 2026-10-21 변경에 반영했다. 관리자 대시보드 및 신규 API 구현은 해당 T01 변경에 포함하지 않았다.

새로 전달된 ERD V1.1에는 `signup_channel`이 없어, 미적용 계정 마이그레이션 `a8c3d1f6e902`를 해당 CHECK와 컬럼을 제거하는 내용으로 수정했다. API는 회원 유형을 `user`로 계산하며 기존 컬럼을 읽거나 쓰지 않는다. 기존 컬럼이 있는 DB와 없는 DB 모두에서 계정 조회·수정·신규 저장이 동작하는지 메모리 DB로 검증했다. 기존 데이터는 실제 마이그레이션 적용 전까지 그대로 남으며, 실제 DB에는 아직 적용하지 않았다. 향후 적용하면 계정 ID와 참조는 보존되지만 제거한 소비자/크리에이터 구분은 복원할 수 없다. downgrade는 해당 컬럼을 `consumer` 기본값으로 다시 만든다. 인증 컬럼 이름 변경 등 ERD 전체 개편은 별도 작업이다.

검증: 관련 백엔드 테스트 101개 통과(회원·인증 47개, 계정 DB 호환·AI·알림 44개, 마이그레이션 10개). AI 질문 HTTP 경계에서 한글·이모지 500자 허용/501자 거절, 공백 질문 거절을 확인했다. 프론트 타입 검사와 AI 안내 전파·질문 길이 경계 검증을 통과했으며, `npm run build -- --webpack`도 전체 정적 페이지 생성까지 통과했다. 빌드 중 샌드박스 파일 생성 권한 오류가 있었으나 같은 명령을 제한 밖에서 실행해 성공했다. 실제 DB 적용과 브라우저 전체 흐름 검증은 아직 수행하지 않았다.

완료 기준: 최신 계약으로 온보딩 요청을 보내면 계정 유형 오류가 없고, DB·API·FE가 같은 규칙을 사용한다. 미정 값은 임의로 확정하지 않으며 변경될 정책을 계약에 명시한다.

보관기간·미정 저장 종류 등 결정이 남았다고 독립 작업을 멈출 필요는 없다. 다만 해당 요구의 완료/출시 판정은 정책 확정과 실제 연결 뒤에 한다.
