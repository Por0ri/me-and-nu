## 화면·API 연결

Pivot 신규 가입은 **약관 → 닉네임 → 애니메이션 분야 → Q1 → Q2 → Q3 → 선택 확인 → 가입 완료** 순서다. 실제 소셜 인증 후의 `onboarding_pending` 세션을 사용하며, 임의의 사용자 ID를 프론트에서 지정하지 않는다.

- **Q1:** `GET /api/v1/onboarding/works`로 이름·별칭을 검색해 작품 1~5개를 선택한다. 검색 지연 중 이전 요청을 취소하고 늦게 도착한 결과가 새 검색을 덮지 못하게 한다. 5개를 골랐으면 추가 선택을 막되 해제는 가능하다. 빈 결과·오류·더 보기·선택 불가 작품을 구분한다. 형식은 시리즈/극장판 등 한국어로 표시하고 이미지 null은 기본 썸네일로 표시한다.
- **Q2:** `POST /api/v1/onboarding/preference-options`로 Topic 전체 활성 장르·소재 칩을 조회한다. 장르와 소재 각각 최소 1개·최대 7개이며, `sourceEntityIds`는 빈 배열도 가능한 작품 힌트다. 작품을 바꾸면 기존 태그 선택을 비우고 안내한다. 같은 작품으로 Q2에 돌아오면 후보를 재검증하고 유효한 선택을 유지한다. 조회 실패 시 다음 단계를 막고 재시도할 수 있다.
- **Q3:** 기존 Q1의 여섯 소비 유형을 재사용하며 하나만 선택한다.
- **완료:** `POST /api/v1/onboarding/complete`에 `answers:{version:2,favoriteEntityIds,preferenceTagIds,consumptionType}`를 보낸다. 성공 응답의 선택 집합·소비 유형과 활성 세션을 확인한 뒤 홈으로 이동한다. 중복 제출 방지, 응답 유실 후 세션 확인, CSRF 갱신, 정책·입력 오류 복구를 유지한다.

검색·후보 API 실패를 가상 작품이나 성공한 저장으로 대체하지 않는다. `/pivot/demo`, `/pivot/preview`의 명시적 가상 데이터는 실서비스 경로에서 사용하지 않는다. 기존 백엔드 V1 답변 호환은 유지한다.

### 생년월일 보류

새 Pivot 흐름은 **닉네임만 수집**한다. 생년월일 필수 입력·날짜 검사·연령 판정·전송을 연결하지 않으며 다른 값으로 추정하지 않는다. 기존 백엔드의 `birthDate` 미지원 계약과 환경별 DB 컬럼 상태는 그대로다. 기존 Consumer 경로와 생년월일 유틸리티는 이번 화면 연결에서 수정하지 않았다. 수집·저장·연령 확인의 최종 정책은 통합 후 결정한다.

이 문서의 최초 가입 검증은 e3 온보딩 revision을 기준으로 수행했다. 후속 서비스 전체의 명시적 target은 e3·캐러셀 f4를 포함하는 **`150a601074af`**이며 [캐러셀 DB·API 문서](CAROUSEL_DB_API_INTEGRATION_2026-10-28.md)를 따른다. 현재 서비스 후보는 150a 단일 head이고 생년월일 삭제 d2 파일을 제외했다. 대상 환경과 활성 `anime` Topic을 먼저 확인한다. 검토한 카탈로그는 아래 명령으로 미리보고, 저장할 때만 같은 대상에 `--apply`를 추가한다.


현재 변경은 통합 작업 공간의 미커밋 상태다. 실제 서버 적용, 공급자 로그인부터 시작하는 실계정 검증, 카탈로그 범위·포스터 보완은 후속이다. 온보딩 저장이 추천 순위나 캐러셀 발행 연결 완료를 뜻하지 않는다. 후속으로 추가한 캐러셀 서비스 어댑터·운영자 검토 경계는 [DB·API 기록](CAROUSEL_DB_API_INTEGRATION_2026-10-28.md), 홈·상세 화면 연결 상태는 [프론트 캐러셀 기록](FRONTEND_CAROUSEL_INTEGRATION_2026-10-28.md)에서 관리한다. canonical 작품 ID와 온보딩 entity ID를 추정 변환하지 않는 기준은 유지한다.
