# Agent 콘텐츠의 서비스 노출 기한

Agent가 명시적으로 `feed_valid_until: null`을 전달하면 새 콘텐츠는 서비스에서도 기한 없이 보관한다. 기사 원문의 행사·판매 종료일은 생성 대상 판정에 쓰며, 이미 저장된 콘텐츠의 공개 만료일로 임의 변환하지 않는다. 명시적인 서비스 만료일이 있으면 그 시각을 그대로 적용한다.

## 적재와 검수

- 만료일 필드 누락·빈 문자열·시간대 없는 날짜는 계속 거부한다. 명시된 날짜는 적재 시점보다 미래여야 한다.
- 새 NULL 적재만 Content의 `ai_judgment_basis`와 Draft의 검수 메타데이터에 `feed_expiry_policy: no_deadline_v1`을 기록한다. 원본 package·이미지·해시·생성 및 검수 이력은 수정하지 않는다.
- 과거 NULL 캐러셀에 표시를 일괄 추가하지 않는다. 표시 없는 과거 콘텐츠는 기존처럼 비노출이며, 재적재로 자동 보정하지 않는다.
- 기본 적재는 `pending_review` / `needs_review` / Draft `checking`이다. Agent 검수 통과는 운영자 승인이 아니다. 운영자 승인 후 기존 공개 조건을 모두 만족해야 피드에 보인다.
- 명시 만료일, 삭제, 반려, 예약 공개, 출처 및 슬라이드 검증은 표시 유무와 관계없이 유지한다. 승인·반려·재적재 시 기존 ID와 감사 기록을 보존한다.

## RAG와 추천

RAG 일정의 `feed_valid_days`는 필수 키다. 명시적인 `null`은 Agent의 `draft.valid_until`을 따르고, 그 값도 NULL이면 기한을 만들지 않는다. 기존 정수 1~365일 정책은 그대로 지원하며 원본보다 긴 기한은 허용하지 않는다. 정책 전체는 계속 SHA 검증 대상이므로 이미 검토된 유한 기한을 몰래 NULL로 바꿀 수 없다.

추천 배치와 API는 같은 공개 조건을 사용한다. 새 NULL 적재에는 30/90일의 대체 만료일을 적용하지 않고, 추천 내부 배열에서만 종료일 없음으로 표현한다. 기존 일반 콘텐츠의 대체 기간, 추천 점수·가중치·회원 및 반응 기록은 변경하지 않는다. DB 마이그레이션은 필요 없다.

## 운영 전환

기존 원본 결과가 NULL 만료일 때문에 적재되지 않았다면 새 적재기로 같은 결과를 다시 검증·적재한다. LLM 재생성이나 원본 결과 수정은 하지 않는다. 이전 실행의 복구·비용·작업 이력을 마감한 뒤 새 날짜의 기사·RAG 스케줄로 전환한다.

기사와 RAG는 한국시간 하루 최대 40회 시도, Agent 검수 통과 20건 목표를 공유한다. 한 번에 한 건씩 처리하고 공개는 운영자 승인 후 진행한다. 코드 배포만으로 유료 생성을 켜지 않으며, 별도로 승인한 활성화 정책·키 마운트·Worker 소유권을 확인한다.

무과금 회귀는 NULL/유한 기한의 중복 적재, 승인 전 비노출·승인 후 노출, 반려·만료·예약 공개, 과거 NULL 보존, RAG 원본 기한 보존 및 정책 해시, 공유 일일 제한과 일자 전환을 포함한다.
