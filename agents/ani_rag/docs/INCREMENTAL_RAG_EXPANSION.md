# RAG 근거를 중복 없이 늘리는 방법

## 목표 흐름

1. MCP 검색은 승인된 근거 출처에서 새 페이지 후보를 찾는다.
2. 후보 ID와 URL을 정규화하고 영속 수집 기록과 대조한다.
3. 이미 읽은 항목이고 다시 확인할 시점도 아니면 원문/속성 조회를 건너뛴다.
4. 새 항목이거나 재확인 시점이면 읽고, 내용 해시를 비교한다.
5. 내용이 바뀌지 않았으면 확인 시각만 갱신한다. 바뀌었으면 새 근거 버전을 저장한다.
6. 벡터 색인에는 새 청크만 추가한다. 같은 청크 텍스트가 있으면 기존 벡터를 재사용한다.
7. 검색은 현재 버전의 근거를 기본으로 사용하고, 이전 버전은 이력으로 보존한다.

## 중복을 가려낼 키

- **출처 내부 ID가 있으면:** `(source_id, source_native_id)`를 우선 사용한다. URL이 바뀌어도 같은 출처 항목인지 찾을 수 있다.
- **출처 내부 ID가 없으면:** `(source_id, canonical_url)`을 사용한다.
- **웹 후보 검색:** 정규화 URL로 같은 작품·콘텐츠 유형 작업의 큐 중복을 막는다. 후보 페이지 본문은 검증 전까지 사실 근거로 저장하지 않는다.
- **내용 및 임베딩:** 정규화한 본문·발췌 해시와 청크 텍스트 해시를 사용한다. 같은 텍스트가 다시 들어오면 벡터 API를 다시 부르지 않는다.

URL 정규화는 원래 URL도 보존하면서 호스트 대소문자, 기본 포트, 조각 식별자, 끝 슬래시를 정리한다. `utm_*`, `fbclid`, `gclid` 같은 추적용 쿼리만 제거하고 페이지 내용을 바꿀 수 있는 매개변수는 유지한다. 예를 들어 `index.html`과 `index.html/`은 중복 확인 때 같은 주소로 취급한다.

## 새 문서와 수정 문서

- 새 문서는 근거 검토 후 RAG 정본에 추가하고 새 청크만 임베딩한다.
- 같은 URL의 내용이 같으면 새 문서·청크·임베딩을 만들지 않는다.
- 내용이 달라지면 새 버전을 저장한다. 이전 버전은 이력으로 남기고 기본 검색에서 제외한다.
- 같은 청크 텍스트가 다른 문서에도 있으면 벡터는 재사용하되 문서별 출처·작품 ID·발행일·청크 위치 연결은 보존한다.
- 벡터 점수는 관련 근거를 찾는 점수다. 사실 확정은 인용된 원문 근거로 판단한다.

## 반복 수집 주기

전 출처에 같은 주기를 적용하지 않는다. 출처별 설정에 수집 간격, 최신순 정렬 기준, 마지막 수집 지점(커서), 다시 훑을 겹침 구간을 둔다. 주기 실행은 최신 자료부터 찾고 직전 구간을 일부 겹쳐 검색해 지연 등록이나 날짜 수정을 잡는다. 이미 읽은 URL은 재확인 시기가 되기 전까지 건너뛴다.

MCP가 ETag 또는 `Last-Modified`와 조건부 요청을 지원하면 재확인에 사용한다. 지원하지 않으면 출처별 간격에 따라 다시 읽고, 본문 해시가 같으면 저장과 임베딩을 건너뛴다.

현재 Firecrawl 검색 어댑터는 `query`, `sources`, `limit`, `objective`를 보낸다. 확인한 Firecrawl Search API 요청 schema에는 페이지 번호·offset·cursor 입력이 문서화되어 있지 않고, 응답의 `totalPages`만으로 다음 결과 페이지를 요청할 수는 없다. 그래서 Firecrawl에는 가짜 커서를 보내지 않는다. 대신 검색 요청에 서로 다른 `query_variants`를 지정하면 DB-backed 큐가 각 검색어를 차례대로 검색한다. 실제 검색 도구가 이어받기 값을 제공할 경우에는 provider가 돌려준 값만 후속 큐 작업에 그대로 저장한다. Firecrawl MCP는 연결 시 실제 도구 입력 schema를 제공한다. 프로젝트 문서에는 2026-11-08에 확인한 도구 이름이 기록돼 있지만, 이 작업 세션의 도구 목록에는 프로젝트 MCP가 노출되지 않아 최신 입력 schema는 다시 확인하지 못했다. [Firecrawl MCP 도구 안내](https://docs.firecrawl.dev/mcp-server/tools), [Firecrawl Search API](https://docs.firecrawl.dev/api-reference/endpoint/search)

## 코드에 추가한 연결과 남은 부분

- 일반 MCP 페이지와 구조화 MCP 항목(Wikidata 등)을 읽기 전에 `rag_source_read_ledger`에서 URL/출처 내부 ID를 확인한다.
- 넓은 웹 후보는 `rag_web_candidate_url_ledger`에 URL과 첫 발견·최근 발견·최근 읽기 시각을 남긴다. 제한된 페이지 본문은 별도 캐시에 30일 보관하고, 만료 본문은 다음 후보 읽기 때 지우되 URL 기록은 유지한다. 같은 URL은 30일 뒤 다시 읽어 갱신한다. 캐시 본문은 후보 원문 재사용용이며 사실 근거로 검색하거나 저장하는 RAG 문서가 아니다.
- 기본 재확인 간격은 30일이다. 수집 요청별로 1시간~1년 범위에서 바꿀 수 있다. 동시에 같은 항목을 처리하는 경우는 짧은 lease로 막고, 읽기 실패는 지수형 대기 후 재시도한다.
- 기존 DB의 문서도 처음 확인할 때 수집 시각을 읽어 최근 자료의 불필요한 재수집을 건너뛴다.
- 완료된 전체 색인 뒤에 새로 적재된 문서만 처리하는 `scripts/update_vector_evidence_index.py`를 추가했다. 청크 ID는 재사용 여부를 확인하고, 벡터는 텍스트 해시가 같으면 재사용한다.
- 색인 갱신기는 기존 색인 DB에서 원본 문서 번호 체크포인트를 이어가고, 원본 RAG DB는 읽기 전용으로 연다.
- 스키마 변경은 [`migrations/0002_source_read_ledger.sql`](../migrations/0002_source_read_ledger.sql)에 준비했다. 아직 어떤 DB에도 적용하지 않았다.
- 웹 후보 큐는 작품·콘텐츠 유형별 평가 작업을 유지하면서, 페이지 읽기만 공유 캐시로 합친다. 같은 URL도 각 작품과 유형의 RAG 대조는 별도로 수행한다.
- 웹 후보 캐시는 `migrations/0003_web_candidate_page_cache.sql`, 장기 URL 기록은 `migrations/0004_web_candidate_url_ledger.sql`에 준비했으며 실제 DB에는 적용하지 않았다. 같은 최종 URL로 리다이렉트되는 서로 다른 요청 URL은 아직 하나로 합치지 않는다.
- 검색 요청마다 `search_run_id`, 검색어 순번, provider 커서는 후속 collection queue payload에 저장된다. Firecrawl처럼 커서가 없는 검색기는 지정된 `query_variants`를 순서대로 소비한다. 반복 웹 검색 계획은 DB에 명시적으로 등록하면 crawler agent가 다음 실행 시각에 큐에 넣는다. 등록된 계획은 없으며 runtime 구성만으로는 계획을 만들지 않는다.
- 반복 검색 계획은 `migrations/0005_recurring_web_discovery_plan.sql`에 준비했지만 미적용이다. 등록된 계획의 다음 실행 시각과 lease는 DB에 기록되고, 중단 뒤 밀린 실행은 한 번으로 합쳐 다음 주기부터 재개한다.
- runtime은 벡터 sidecar 연결과 같은 모델의 query embedder를 명시적으로 받으면 생성·웹 후보 대조에 cosine 검색기를 쓴다. 기본 연결은 기존 lexical 검색기이며, 실제 프로세스에 벡터 연결은 설정·실행되지 않았다.

## 구현 순서

1. 서버가 사용할 전용 RAG DB에 migrations 0002-0005를 순서대로 적용한다. 현재 DB에는 적용하지 않았다.
2. 페이지가 수정되면 새 버전을 만들고 기본 검색에서 이전 버전을 제외하는 현재 버전 표시를 추가한다.
3. `update_vector_evidence_index.py`를 주기적으로 실행해 새 근거만 색인한다.
4. 반복 검색 계획을 명시적으로 등록하고, 검색어 묶음과 주기를 정한다. provider가 커서를 줄 때만 후속 페이지 작업으로 이어간다.
5. 배포 worker에 읽기 전용 vector sidecar 연결과 동일 임베딩 모델 query adapter를 주입하고, 점수 기준을 실제 자료에서 점검한다.

코드와 migration 파일만 준비했다. 반복 수집, DB 스키마 변경, MCP 호출, 벡터 갱신, 워커 실행은 하지 않았다.
