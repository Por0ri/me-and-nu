# 애니 콘텐츠 출처 자동수집 가능성 검토

> 조사 기준일: 2026-10-21
> 상태: 실행 시험 후 `config/sources.json`에서 PR TIMES와 AnimeSchedule RSS만 후보 발견용 자동수집 활성 상태로 유지. 둘 다 공식 1차 콘텐츠 근거 출처는 아니다. 나머지 출처는 삭제하지 않고 비활성 상태로 보존.
> 전제: 본 프로젝트는 현재 수업 과제용 비상업 프로젝트이며, 상업적 이용을 전제로 판정하지 않는다. 이 전제는 플랫폼별 접근·저장·AI 입력·저작권 정책을 면제하지 않는다.
> 목적: 앞선 콘텐츠 유형별 후보 출처를 에이전트가 자동 수집할 때 어떤 경로를 쓸 수 있는지와 추가 허가/확인이 필요한 조건을 정리한다.

## 판정 원칙

- **피드/API 존재**는 기술적으로 자동화할 수 있다는 뜻이지, 본문·이미지의 재사용 허가나 상업적 이용 허가가 아니다.
- **robots.txt 허용 또는 404**는 이용약관·저작권 허가를 대신하지 않는다. 403/차단은 우회하지 않는다.
- 우선순위는 `공식 RSS/API → 공식 sitemap/공개 목록에 대한 저빈도 변경 감지(정책 허용 확인 후) → 미지원/차단은 수집 제외`다.
- 에이전트가 외부 생성형 LLM에 원문을 보낼 수 있는지는 일반 웹 크롤링과 별도 허가 문제다. `ai-train=no`를 `ai-input=yes`로 해석하지 않는다.
- 현재 이 문서는 출처 운영 설계 검토 자료다. 목록에 나온 어떤 사이트도 이 문서만으로 에이전트에 활성 등록하면 안 된다.

## 자동화 판정 요약

| 판정 | 의미 | 현재 후보 예 |
|---|---|---|
| `API/RSS-조건부` | 공개 피드/API가 있으나 이용 목적·등록·저장·재게시 조건 확인이 선행돼야 함 | PR TIMES, AnimeSchedule, AniList, Reddit API, ANN feed/API 후보 |
| `공식 HTML-조건부` | 사이트 자체가 사실 출처로 쓸 만하고 공개 페이지는 확인되나, 현재 공개 API/RSS나 자동수집 허가가 확정되지 않음. 사이트별 허용이 확인되면 sitemap/목록 기반 저빈도 polling 검토 | 작품 공식 사이트, 행사 주최자/제조사 사이트 대부분 |
| `보조 HTML-조건부` | 뉴스/리뷰/캘린더의 HTML을 기술적으로 읽을 수 있으나 1차 사실 출처가 아니며, 약관/수집 조건은 미확정 | MANTANWEB, Anime Hack, Anime! Anime!, Dengeki Online 등 |
| `권한/기술 보류` | API 승인·약관 확인이 필요하거나 403/불안정 접근·명시적 봇 차단 등 | 커뮤니티, 일부 매체·색인, 프리미엄 판매 페이지 |
| `자동수집 제외` | 현재 정책 신호나 접근 제한 때문에 자동 수집을 채택하지 않음 | AnimeMaps, 승인 없는 커뮤니티 게시물/이미지, 차단 경로 |

**비상업 과제 기준 결론: 자동 수집 후보는 분명히 있다.** 단, 피드/API가 있다는 것만으로 이용 조건까지 모두 충족되는 건 아니다. 수업 과제 범위에서 쓸 수 있는 공개 피드/API는 우선 후보로 두고, 개인 전용 이용조건·대량수집 제한·AI 입력·콘텐츠 게시 권리와 robots/접근 제한이 남은 곳은 조건부로 분리한다.

## 현재 코드의 읽기 전용 연결 시험 (2026-10-21)

현재 `config/sources.json`의 허용 상태를 대상으로 `collect_candidates(limit=20, timeout=8)`를 직접 실행했다. 이 호출은 후보를 메모리에서 추출할 뿐, SQLite나 발견 결과 파일에는 저장하지 않는다.

| 확인 결과 | 실제 관찰 | 해석 |
|---|---|---|
| [PR TIMES 공개 RSS](https://prtimes.jp/index.rdf) | 후보 5건 파싱 | RSS 경로와 현재 파서가 동작함. 후보 사실은 발표 기업·주최자 원문에서 확인해야 함. |
| [AnimeSchedule RSS](https://animeschedule.net/jpnrss.xml) | 후보 4건 파싱 | RSS 경로와 현재 파서가 동작함. 일정 데이터 범위에 한정. |
| Reddit / 루리웹 커뮤니티 HTML | robots 확인 단계에서 실패(접근 차단 응답 또는 연결 시간 초과) | 수집 결과 없음. 차단을 우회하지 않고 현재 자동 경로에서 제외하는 편이 맞음. |
| 공식 사이트 HTML 목록 | `discover` 대상이 아님 | 2026-10-21 업데이트 기준, 현재 레지스트리에 활성 공식 1차 HTML 출처가 없다. 개별 페이지 수집도 출처 재검토가 완료되기 전에는 중단된다. 목록 전체를 훑어 새 글을 발견하는 기능 역시 아직 운영되지 않는다. |
| AniList GraphQL | 상태 `terms_review` | 실행되지 않음. 현재 API 처리도 일반 범용 API 어댑터가 아니라 AniList 전용 경로다. |
| YouTube 공식 채널 RSS | 상태 `setup_required` | 실제 채널 ID 기반 `feed_url` 설정 전에는 실행되지 않음. |

### 이번 실행만으로 내릴 수 있는 결론

- **현재 바로 자동 발견이 실증된 경로는 RSS 2개**이며, 이번 호출에서 총 9건을 추출했다. 두 피드는 후보 발견 전용이며, 그 숫자는 해당 시점의 샘플 결과이지 매일 보장되는 양이나 고유한 사실 수가 아니다. 후보 호스트에 대응하는 활성 공식 1차 출처가 없으면 콘텐츠 생성으로 넘어가지 않는다.
- 유형별 93개 조사 후보 전체를 확인한 것은 아니다. 활성 레지스트리 중 공식 HTML 출처도 자동 목록 탐색 상태가 아니며, 실행 시험에서 통과한 두 피드 외에는 자동 비활성 상태로 유지한다.
- 따라서 “93개 전부 자동수집 가능”이라고 판정할 수 없다. 현재 에이전트에서 동작하는 `discover`는 피드 중심이며, 각 유형을 넓게 자동 발견하려면 사이트별 RSS/API 경로 또는 허용이 확인된 HTML 목록 어댑터를 추가해야 한다.
- 이 시험은 연결성과 파싱 여부만 확인했다. 이용약관, 게시물·이미지 재사용, LLM 입력 허용을 승인한 결과가 아니다.

| 캐릭터 | 작품 공식 캐릭터 페이지; AniList/ANN/AniDB 색인 | 공식 작품 페이지에서 링크·필드 조회. 색인은 좁은 entity lookup에만 사용. AniList mass collection 금지, ANN/AniDB API 정책 확정 전 비활성 |
| 큐레이션 | Crunchyroll Awards, Anime Trending, Anime Corner polls, AniList, MyAnimeList | 공개 집계 페이지에서 조사 주체·기간·표본·방법 정보도 함께 가져올 수 있을 때만. 특정 순위 숫자만 크롤링해 일반 팬덤 선호로 확대하지 않음. MAL API/승인 범위 확인 전 보류 |
| 음악 | Lantis, King Records, Pony Canyon, Sony Music Japan, Aniplex, FlyingDog; ANN/MANTAN; Apple Music/Spotify | 레이블의 공식 뉴스/카탈로그 업데이트를 저빈도 감지하는 후보. 스트리밍 카탈로그는 지역별 발매 확인 보조. 서비스 API 조건, 재배포, 자켓/음원 권리 별도 검토; Apple/Spotify는 뉴스 출처 대체가 아님 |

## 등록 전에 충족해야 할 자동화 게이트

출처마다 다음을 채우고 모두 통과하기 전에는 `active`로 넣지 않는다.

1. **인터페이스**: 공식 RSS/API인지, 아니면 HTML/sitemap인지와 정확한 경로를 고정한다. 검색/개인 계정/결제/차단 경로를 사용하지 않는다.
2. **규정**: 최신 이용약관과 robots를 확인하고 자동 수집, 상업적 서비스 이용, AI 입력, 결과물 게시의 허용 범위를 각각 기록한다. 약관이 불명확하면 운영자 승인 없이는 보류한다.
3. **최소 수집**: 최초 수집은 `제목, URL, 발행/행사일, 출처명, 원문 언어`로 제한한다. 내용 전문/댓글/이미지는 원칙적으로 저장하지 않는다.
4. **요청량**: 피드 권고 주기를 지키고 HTML polling은 더 긴 간격, 캐시/ETag/Last-Modified, 지수 백오프, 429/403 즉시 중단을 적용한다. 재시도로 제한을 우회하지 않는다.
5. **권리와 삭제**: 이미지/영상/인용문은 별도 라이선스 없으면 생성물로 복사하지 않는다. 출처 삭제·정정·권리자 요청을 추적하고 해당 후보/생성물에 반영한다.
6. **검증**: 공식 원문으로 작품(`menu_work_id`), 국가, 날짜, 이벤트 시작/종료일을 검증한다. 출처 간 충돌·페이지 변경·번역 불확실성은 자동 게시 대신 오류 큐에 보낸다.
7. **상태 구분**: `discovered → policy_pending → approved_metadata_only → approved_content → disabled` 단계로 관리한다. 유형 태그만으로 출처를 자동 활성화하지 않는다.

## 비상업 과제 전제로 보정한 권고 결론

1. 초기 자동 수집 MVP는 **공식 RSS/API 기반 메타데이터 후보 수집**부터 한다. 지금 확인된 공개 기술 후보는 TV Tokyo RSS, PR TIMES RSS(보도/일반 이용 조건 구분), AnimeSchedule API/RSS(비상업 프로젝트 범위·요청 조건 준수), Crunchyroll News RSS(일본 가용성/현행 상태 재검증), ANN RSS/API(현행 공식 조건 재확인)다. 비상업 과제라는 점은 상업 라이선스 부담을 줄이지만 각각의 이용 약관을 없애지는 않는다.
2. 작품 공식 포털, 행사 주최자, 굿즈 제조사, 소속사 사이트는 유형별로 무차별 크롤링하지 말고 **작품/도메인별 allowlist + 페이지 패턴 + 최소 주기**를 정한다. RSS/API가 없는 곳은 자동 수집 허용을 별도 확인할 때까지 비활성으로 둔다.
3. 커뮤니티 유머는 승인 받은 플랫폼 API가 없다면 자동화 MVP에서 제외한다. 공개 웹 게시물을 스크랩해 LLM에 넣는 방식은 채택하지 않는다.
4. 이미 설정된 `active` 상태의 21개 출처는 이 문서로 검증·승인된 것이 아니다. 나중에 구현할 때 각 출처를 이 게이트에 대조해 과제용 비상업 수집 가능 여부를 다시 정한다.

이 문서는 법률 의견이 아니라 제품·기술용 출처 검토다. 사이트 조건은 바뀔 수 있으며 실제 이용 전 해당 사이트의 최신 규정과 운영자 답변을 확인해야 한다.
