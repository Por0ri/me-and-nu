# 콘텐츠 생성 중 할루시네이션 통제 방식

이 문서는 현재 `ani_menu_agent` 코드에서 원문 수집부터 콘텐츠 검수까지 사실 근거를 연결하고, 근거가 부족하거나 잘못 사용된 내용을 처리하는 방식을 설명합니다. 코드에 구현된 통제와 그 한계를 구분합니다.

## 한눈에 보는 흐름

```text
활성 출처의 페이지 본문
  → LLM이 사실 후보와 원문 인용문 추출
  → 인용문이 실제 본문에 있는지 코드로 확인
  → 사실(Fact) ID를 카드·상세글에 연결
  → 결정적 코드 검사
  → 별도 검수 호출이 카드와 상세글을 근거 사실에 대조
  → 통과 / 담당 수정 / 크롤러 보완 / 탈락 보관
```

## 단계별 통제

### 1. 생성 근거가 될 출처를 제한

일반 사실 콘텐츠의 페이지 추출은 출처 레지스트리에 등록되어 있고 활성 상태이며, 역할이 `primary`, `editorial`, `reference`인 출처만 받습니다. 캡처 본문이 비어 있으면 사실 추출을 진행하지 않습니다.

발견 전용 출처의 목록·후보 페이지는 후보를 찾는 맥락으로 쓰일 수 있지만, 그 페이지의 요약 문구를 그대로 사실 근거로 승격하지 않습니다. 가능한 경우 후보 기사에서 등록된 근거 출처의 원문 링크를 찾아 해당 페이지를 별도로 캡처합니다. 원문을 특정하지 못하면 원문 미확인 상태로 남겨 생성 단계에 보내지 않는 흐름이 있습니다.

### 2. LLM이 사실 후보마다 원문 인용문을 붙임

페이지 추출 LLM은 제목, URL, 수집 시각, 캡처된 본문을 받아 구조화된 사실 후보를 만듭니다. 각 후보에는 원문에 실제로 있는 `evidence_quote`를 넣도록 지시합니다. 출처 본문은 신뢰할 수 없는 입력으로 취급하며, 본문 안에 포함된 지시문이나 외부 행동 요청은 따르지 않도록 프롬프트에서 명시합니다.

추출 결과는 코드가 다시 확인합니다.

- 인용문이 비어 있거나 캡처 본문에 그대로 존재하지 않으면 사실 후보에서 제외합니다.
- 중복 사실을 제거합니다.
- 사실마다 ID, 출처 ID, 원문 인용문을 저장합니다.
- 사실 수가 제한을 넘으면 주제 관련성과 사실 유형 등을 기준으로 우선순위가 높은 사실을 보존합니다.
- 행사 시작일·종료일은 인용문에서 날짜를 읽어 추출 결과와 맞지 않으면 구조화된 날짜를 비웁니다.
- 행사 장소도 인용문이 실제 본문에 있고 장소명이 그 인용문에 포함되는지 확인합니다.

이 단계의 `verified=True`는 **추출된 사실이 원문 인용문과 연결되었다는 의미**입니다. 외부의 독립된 두 번째 자료로 사실을 교차 검증했다는 뜻은 아닙니다.

### 3. 카드와 상세글이 사실 ID를 사용

콘텐츠 생성 프롬프트는 사실 설명과 원문 인용문을 함께 받아, 사실 주장은 제공된 검증 사실만 사용하도록 지시합니다. 각 카드의 사실 주장에는 이를 뒷받침하는 `fact_id`를 연결해야 합니다. 근거가 부족하면 내용을 만들어 채우지 말고 추가 조사 대상으로 돌리도록 합니다.

상세글 작성도 근거 사실을 입력으로 받으며, `detail_fact_ids`에 실제 사용한 사실 ID를 반환합니다. 카드에 사용한 사실이 상세글 근거 목록에서 빠졌는지, 알 수 없는 사실 ID가 들어갔는지는 코드가 확인합니다. 상세글에 출처 문장과 무관한 새 사실을 쓰지 말고, 추론을 사실처럼 덧붙이지 않도록 프롬프트가 제한합니다.

유머·팬 반응은 사실과 구별해 표현할 수 있습니다. 커뮤니티의 일부 의견을 팬덤 전체의 합의나 다수 의견으로 바꾸어 말하지 않도록 별도 지시가 있습니다. 리뷰 의견도 객관적 사실처럼 쓰지 않고 출처의 평가로 귀속해야 합니다.

### 4. 코드가 구조적 오류와 일부 근거 오류를 검사

결정적 검사(`quality.py` 등)는 다음과 같은 문제를 찾습니다.

- 사실에 연결된 출처가 패키지에 존재하지 않음
- 정보 콘텐츠에서 사실이 미검증 상태임
- 카드가 존재하지 않는 `fact_id`를 참조함
- 상세글의 사실 ID가 없거나, 카드에서 쓴 사실이 상세글 근거 목록에서 누락됨
- 상세글 사실 ID가 실제 사실 또는 출처에 연결되지 않음
- 행사 종료일이 지났는데 행사 중인 것처럼 표현됨
- 일부 행사·응모·판매 유형의 마감 정보가 지났거나 필수 근거 정보가 누락됨
- 작품 연결, 이미지 연결, 카드 구성 등 다른 구조 규칙 위반

사실·출처 관련 차단 이슈는 높은 전체 점수로 상쇄되지 않습니다. 이슈의 심각도와 담당에 따라 수정 단계로 보내거나, 크롤러에 자료 보완을 요청하거나, 탈락 보관합니다.

### 5. 독립 검수 호출이 문장 의미를 근거와 대조

코드 검사를 통과한 패키지는 별도의 검수 호출로 전달됩니다. 검수 입력에는 출처 정보, 검증 사실, 카드 문구와 사실 ID, 상세글과 상세글 사실 ID가 포함됩니다. 검수는 각 사실 주장이 연결된 근거를 벗어나지 않는지, 날짜·고유명사·번역·문맥이 자연스럽고 정확한지 살핍니다. 렌더링된 카드 미리보기도 전달해 이미지 적합성 및 화면 문제를 별도로 평가합니다.

상세글은 카드와 따로 검수하며, 내용의 사실적 뒷받침뿐 아니라 글의 일관성, 한국어 자연스러움, 행사 정보 완전성도 평가합니다. 검수에서 나온 이슈는 레지스트리의 차단·수정·경고 등급과 담당에 따라 라우팅됩니다. 수정 가능한 문제는 수정 루프를 거치고, 근거 자료 자체가 부족한 경우에는 크롤러 보완으로 돌립니다.

## 할루시네이션 통제가 보장하지 않는 것

현재 구조는 근거 없는 내용을 줄이기 위한 여러 겹의 통제이지, 모든 오류를 완벽히 차단하는 증명 시스템은 아닙니다.

1. **원문 인용문 존재만으로 요약 의미가 증명되지는 않습니다.** LLM이 원문 인용문을 정확히 복사하면서도 그 의미를 잘못 요약할 수 있습니다. 이 의미 차이는 코드의 문자열 포함 검사만으로는 잡히지 않고, 주로 독립 검수 호출에 의존합니다.
2. **검수는 별도 단계의 LLM 판단입니다.** 별도 검수 프롬프트와 호출을 사용하지만, 코드만으로 의미상 사실 여부를 확정하는 것은 아닙니다. 모델의 실수나 놓침 가능성이 있습니다.
3. **캡처되지 않은 정보는 검사할 수 없습니다.** 동적 페이지, 펼쳐보기 영역, 이미지 포스터 안의 글자, 캡처 본문에 포함되지 않은 연결 페이지는 현재 추출 입력에 없으면 검수 대상이 되지 않습니다. 이미지 파일이 패키지에 있다는 것만으로 이미지 속 문구까지 사실 근거로 추출되는 것은 아닙니다.
4. **작품 ID 연결은 사실 검증과 별개입니다.** 제목·별칭·작품 매칭 절차에서 잘못 연결되면 사실 자체가 맞더라도 다른 작품 콘텐츠처럼 묶일 수 있습니다. 작품 식별 결과와 각 문장의 사실 근거를 별도로 확인해야 합니다.
5. **한 출처의 오류는 그대로 전파될 수 있습니다.** 인용문이 원문에 실제로 있더라도 원문 자체가 오보·오류일 수 있습니다. 사안에 따라 공식 공지, 티켓 판매처, 작품 권리자 등 다른 적절한 출처와 교차 확인이 필요합니다.

## 로그와 추적성

사실 ID와 출처 ID, 원문 인용문, 카드별 사실 ID, 상세글 사실 ID, 검수 이슈와 판정은 콘텐츠 패키지·검수 보고서에 연결됩니다. 이를 통해 어떤 문장이 어느 사실과 출처를 근거로 작성됐고, 어떤 검수 판단을 받았는지 역추적할 수 있습니다. 이 연결은 근거를 찾기 쉽게 하지만, 그 자체가 해당 사실의 참을 보장하지는 않습니다.

## 관련 구현 파일

- `src/ani_menu_agent/extraction.py` — 페이지 사실 후보 추출, 원문 인용문 확인, 날짜·장소 근거 확인
- `src/ani_menu_agent/generation.py` — 사실 기반 카드 작성 지침과 카드별 사실 ID 연결
- `src/ani_menu_agent/agents/content_generation/detail_writer.py` — 상세글 작성 및 상세글 사실 ID 연결
- `src/ani_menu_agent/quality.py` — 결정적 사실·출처·카드·상세글 검사와 점수 판정
- `src/ani_menu_agent/agents/reviewer/agent.py` — 독립 검수 입력 구성, 이미지 미리보기 전달, 검수 호출
- `src/ani_menu_agent/agents/reviewer/prompt.py` — 주장 대 근거, 번역, 상세글 검수 기준
- `src/ani_menu_agent/review_rules.py` — 이슈 코드별 심각도·담당·조치 정책
- `src/ani_menu_agent/nodes.py` — 검수 결과에 따른 수정·크롤러 보완·통과·탈락 라우팅
- `src/ani_menu_agent/policy.py` — 사실 수, 점수·수정·비용 관련 정책값

이 문서는 위 구현을 설명하는 문서이며, 검수 기준이나 에이전트 동작을 변경하지 않습니다.
