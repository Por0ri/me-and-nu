# 작품 미연결 콘텐츠와 검수 대기열 설계

## 왜 별도 검수 화면이 필요한가

현재 자동 생성 파이프라인은 후보를 작품 ID에 연결하지 못하면 생성 전에 멈춘다. 이 규칙은 특정 애니 작품의 소식에는 안전하지만, 애니 페스티벌·코스프레 행사·복수 작품 합동 행사처럼 단일 작품 ID가 본질적으로 없는 콘텐츠까지 차단한다. 이런 행사는 작품 연결 실패가 아니라 **작품 범위가 없는 행사**로 분류해야 한다.

새로 발견된 애니메이션도 자동으로 `menu_works.csv`에 넣지 않는다. 확인 대기 상태로 보관하고, 검수 화면에서 기존 작품 연결 또는 신규 작품 제안으로 처리한다. 기준 작품 CSV를 로컬에서만 바꾸면 팀원 데이터와 갈라지므로, 신규 작품은 별도 제안 목록에 보존하고 담당자가 정본에 반영한다.

## 세 가지 분류를 분리한다

1. **콘텐츠 유형**: news, event, goods, character, review, humor, guide, curation, music, people.
2. **대상 범위**: 단일 작품, 여러 작품, 작품 없는 애니 업계·팬 행사, 창작자, 미확정.
3. **작품 연결**: 검증된 `menu_work_id` 0개 이상. 0개라고 해서 자동으로 비애니 콘텐츠라고 판정하지 않는다.

작품 ID 여러 개는 실제 콜라보·복수 작품 큐레이션처럼 원문이 여러 작품을 명시할 때만 허용한다. 신카이 마코토 감독의 여러 영화가 단지 소개 문장에 나열됐다는 이유로 여러 ID를 자동 연결하지 않는다.

## 검수 대기열에 넣을 사례

- 작품명을 확정할 수 없지만 원문이 애니메이션 관련임은 분명한 행사
- 작품 타이틀은 확인되지만 현재 정본 카탈로그에서 ID를 찾지 못한 신작
- 링크된 특설 사이트·티켓 사이트를 확인해야 작품 또는 주최 정보를 확정할 수 있는 후보
- 작품 ID는 매칭됐지만 행사·굿즈·인물 등 콘텐츠 유형이 서로 충돌하는 후보
- OCR 결과와 본문·예매처의 일정·가격이 일치하지 않는 후보

검수 화면은 자동 검수 결과를 덮어쓰지 않는다. 검수자의 명시적인 판정과 이유를 별도 감사 이력으로 남긴다.

## 화면에서 제공할 결정

각 대기 항목에는 원문 제목·URL·발견 출처·본문 요약·이미지·링크 후보·자동 작품 매칭 근거·유형 신호·날짜·지역을 한 화면에 보여준다. 검수자는 다음 중 하나를 선택한다.

- **기존 작품 연결**: 작품 검색 후 한 ID 또는 실제 콜라보·큐레이션에 필요한 복수 ID를 선택한다.
- **작품 없는 애니 행사로 분류**: 애니메이션 산업·팬덤 행사임을 원문에서 확인한 경우 작품 ID 없이 event 유형, 주제, 지역, 일정으로 생성 대기열에 보낸다.
- **신규 작품 제안**: 표시명·원문 표기·로마자/영문 별칭·하위 작품 여부·근거 URL을 기록한다. 정본 CSV는 자동 변경하지 않는다.
- **추가 근거 요청**: 공식/주최/예매 링크 확인이 필요하면 보류한다.
- **제외**: 애니 관련이 아니거나 신뢰할 원문이 없으면 사유를 남기고 제외한다.

## 권장 상태 흐름

`discovered → identity_review`에서 작품 단위 후보와 작품 없는 행사 후보를 나눈다. 기존 ID 연결 또는 행사 범위 판정 후에만 `generation_ready`로 진행한다. 신규 작품 제안은 `work_proposal_pending`으로 따로 보관하고, 정본 반영 전까지는 자동으로 작품 기반 개인화에 넣지 않는다.

생성 뒤에는 현재 독립 검수를 그대로 적용한다. 사람의 유형 판정이나 작품 연결은 사실 검증·번역·이미지 적합도 검수를 통과했다는 뜻이 아니다.

## 저장 필드 제안

- `entity_scope`: `work | multi_work | anime_event | creator | unknown`
- `menu_work_ids`: 검증된 ID 배열; `anime_event`는 빈 배열 허용
- `content_type`: 기존 유형 enum
- `topic_tags`, `region`, `event_start`, `event_end`
- `identity_status`: `matched | workless_event | pending | proposed | rejected`
- `identity_evidence`: 제목·구조화 메타데이터·공식/주최 링크별 근거와 신뢰도
- `review_decision`, `reviewer_id`, `reviewed_at`, `review_reason`
- 신규 작품 제안용 `proposed_work` 객체와 근거 URL; `menu_works.csv` 쓰기 권한과 분리

## 피드 연동 원칙

작품 ID가 있는 콘텐츠는 사용자의 선호 작품으로 개인화한다. 작품 ID가 없는 애니 행사 콘텐츠는 event 유형, 관심 주제(애니 페스티벌·코스프레), 지역, 날짜로 추천한다. 백엔드가 `menu_work_ids` 빈 배열을 허용하고 해당 콘텐츠를 전역/관심사 피드 후보로 노출하는지 확인한 뒤 생성 경로를 열어야 한다. 이 부분은 현재 에이전트 저장만으로 서비스 피드에 노출된다고 가정하지 않는다.

## 구현 위치

현재 저장소에는 Python 에이전트와 SQLite/PostgreSQL 저장 계층이 있으며, 별도 관리자 웹 프론트엔드가 없다. 따라서 검수 페이지 UI 자체는 백엔드/프론트엔드 저장소에서 만들어야 한다. 에이전트 쪽은 미연결 사유, 작품 매칭 근거, CTA 목적지 확인, OCR 근거와 출처를 API/DB에 전달하는 계약을 제공해야 한다.
