# 크롤러 유형과 수집 lane 분리 기준

## 핵심 결정

`agents/crawlers/`의 10개 파일은 수집 방식별 독립 크롤러가 아니라, 기존 `TypeCrawlerAgent` 공통 흐름에 콘텐츠 유형별 역할·허용 출처 역할·키워드 신호를 제공하는 선언 모듈이다. 따라서 파일 이름의 콘텐츠 유형만 보고 `ani_rag`로 통째로 옮기거나 `ani_me;nu`에서 삭제하지 않는다.

새 구조의 lane은 **자료가 얼마나 오래 유효한지와 어떤 방식으로 확보하는지**를 나타낸다. 콘텐츠 유형은 **그 자료로 어떤 종류의 콘텐츠를 만들지**를 나타낸다. 하나의 콘텐츠 유형에도 기간성 자료와 evergreen 자료가 섞일 수 있으므로, 최종 라우팅은 출처·페이지·후보 레코드 단위에서 결정해야 한다.

현재 `config/source_type_map.json`은 출처 endpoint가 지원할 콘텐츠 유형을 정한다. 기간 중요/evergreen을 구분하는 lane 설정은 아직 없다. `ani_rag/config/sources.evergreen.json`은 비어 있는 초안이며, 아직 MCP 수집 구현을 대체하지 않는다.

## 유형별 1차 분류

| 기존 역할 파일 | 1차 분류 | 판단 근거와 처리 방향 |
|---|---|---|
| `event.py` | 기간 중요 | 전시·팝업·콜라보·상영의 장소와 명시적 행사 기간을 수집한다. 기간성 수집기 책임에 해당한다. |
| `goods.py` | 기간 중요 | 상품·예약·판매·발매 가격과 기간이 중심이다. 기간성 수집기 책임에 해당한다. |
| `news.py` | 대체로 기간 중요 | 신작 발표·속편·방영/스트리밍 일정·PV 등 최신 발표를 다룬다. 다만 모든 발표가 곧 만료된다는 뜻은 아니므로 날짜·유효성은 레코드별로 관리한다. |
| `character.py` | RAG 대상 | 인물 식별·프로필·생일·관계를 다룬다. 기존 모듈은 MCP reader가 아니므로 요구사항과 검증 항목을 참고하고, 구현은 별도 RAG 작업에서 설계한다. |
| `guide.py` | RAG 대상 | 작품 소개·회차/아크 순서·용어·세계관을 다룬다. 공식·참고 문서 검색과 근거 보존을 별도 RAG 작업에서 설계한다. |
| `people.py` | RAG 대상 | 성우·감독·작가 프로필과 크레딧, 관련 자료를 RAG 경로가 담당한다. 신규 발표 자료도 원문 발행일과 작품 연결을 보존한다. |
| `music.py` | RAG 대상 | 곡·아티스트·크레딧·음악 관련 자료를 RAG 경로가 담당한다. 발매일·예약 정보는 기간 민감 필드를 보존하고 만료/최신성 기준을 별도로 적용한다. |
| `humor.py` | RAG 대상 | 사용자의 lane 배정 결정에 따라 RAG 프로젝트가 담당한다. 커뮤니티 밈·투표·토론과 출처가 확인된 제작 비하인드·메이킹은 서로 다른 근거 유형으로 구분하고, 시점 민감 신호를 evergreen 사실로 색인하지 않는다. |
| `curation.py` | RAG 대상 | 사용자의 lane 배정 결정에 따라 RAG 프로젝트가 담당한다. 투표·랭킹은 조사 기간·표본·집계 방법·원문 맥락을 함께 보존한다. |
| `review.py` | RAG 대상 | 사용자의 lane 배정 결정에 따라 RAG 프로젝트가 담당한다. 평론·감상은 사실과 구분하고 작성자·발행일·주장·원문 근거를 보존한다. |

## 이동·삭제 가능 조건

현재 파일을 삭제하거나 이동하는 조건은 다음과 같다.

1. `ani_rag` 또는 기간 수집기에 대체 경로가 구현되어 해당 입력과 provenance를 저장할 수 있다.
2. `cli.py`, `source_discovery.py`, 크롤러 registry, 설정 파일에서 해당 모듈을 참조하는 경로를 모두 확인한다.
3. 기존 콘텐츠 유형 지원이 사라지는지 확인하고, 새 데이터 수집 lane과 콘텐츠 유형 연결 정책을 문서화한다.
4. 원본 파일의 기존 변경사항을 보존하고, 이동/삭제 기록을 남긴다.
5. 새 경로의 코드 검토와 사용자가 요청한 범위의 검증이 끝나기 전에는 기존 경로를 제거하지 않는다.

위 표는 lane 소유권 결정이며 코드 이동이 완료됐다는 뜻은 아니다. `ani_rag` 구현은 별도 작업으로 진행한다. 현재 `ani_me;nu`의 기존 프로필 파일들은 공통 `TypeCrawlerAgent`, `crawl-type`, source discovery 및 기존 저장·생성 흐름에 연결돼 있으므로, 이 문서 갱신에서는 파일을 옮기거나 삭제하지 않는다. 기간 lane의 새 경로와 RAG 경로가 각각 연결되고 기존 CLI 참조를 함께 정리하는 별도 컷오버 단계에서만 불필요해진 프로필을 제거한다.

## 다음 구현 작업

- `ani_me;nu`에 기간 중요 출처와 후보를 명시하는 lane 메타데이터를 정의한다. 기존 `source_type_map.json`을 lane 맵처럼 재사용하지 않는다.
- `ani_rag` 구현은 이 작업 범위 밖이다. 별도 작업에서 MCP search/read 인터페이스, 근거 문서 형식, 작품 ID 연결, RAG chunk/index 계약을 설계한다. 기존 크롤러 파일의 단순 복사는 대체 구현으로 취급하지 않는다.
- 생성·검수는 두 수집 경로가 공유하는 downstream으로 유지한다. 생성·검수 에이전트 코드와 작품 정본을 각 수집 폴더에 중복 복사하지 않는다.
- lane 전환이 끝난 뒤에만 옛 CLI/registry 경로에서 불필요해진 유형별 후보 수집 연결을 단계적으로 걷어낸다.
